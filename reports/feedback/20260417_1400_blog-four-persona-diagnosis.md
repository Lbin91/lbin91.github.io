## 1. 시니어 프론트엔드 엔지니어 관점

### 총평: 기술적 기반은 양호하나, 프로덕션 수준에 미달

#### 잘 된 부분

| 항목 | 평가 |
|------|------|
| 정적 사이트 생성기 선택 | GitHub Pages + Jekyll은 개발자 블로그로 최적의 선택. 빌드/배포 자동화, 무료 호스팅, 마크다운 작성 |
| 테마 선택 | Minimal Mistakes는 검증된 Jekyll 테마. 반응형, 접근성 기본 탑재, 활발한 유지보수 |
| 플러그인 구성 | jekyll-sitemap, jekyll-feed, jekyll-include-cache 등 필수 플러그인은 잘 갖춤 |
| 퍼머링크 구조 | `/:categories/:title/` — SEO 친화적, 키워드 포함 URL |
| 코드 블록 | `kramdown` + 구문 강조 기본 제공, 기술 블로그에 적합 |

#### 치명적 문제

**1. 완전한 날것 상태 (Zero Customization)**

```
커스텀 CSS: 0줄
커스텀 레이아웃: 0개
커스텀 인클루드: 0개
커스텀 SCSS 오버라이드: 0개
```

프로젝트 전체가 `_config.yml` 한 개와 12개의 마크다운 파일뿐. `_layouts/`, `_includes/`, `_sass/` 디렉토리가 존재하지 않음. 이건 "블로그를 만든 것"이 아니라 "테마를 설치만 한 것".

**2. 언어 설정 오류 — `<html lang="en">`**

모든 콘텐츠가 한국어인데 HTML lang 속성이 `en`으로 설정되어 있음.

영향:
- 스크린 리더가 영어 음성 엔진으로 한국어를 읽으려 시도
- 브라우저 자동 번역이 불필요하게 영어→한국어 번역 제안
- Google 검색에서 한국어 페이지로 인식되지 않을 가능성

수정 방법: `_config.yml`에 `locale: "ko-KR"` 추가

**3. 댓글 시스템 고장**

`_config.yml`에 `comments: true`가 설정되어 있지만, 실제 댓글 제공자(Disqus, Giscus, Utterances)가 하나도 구성되어 있지 않음. 방문자에게 깨진 댓글 영역이 보이거나, 아예 아무것도 렌더링되지 않음.

**4. 검색 기능 반쪽짜리**

`jekyll-algolia` gem은 포함되어 있으나 API 키 설정이 없음. 현재 Lunr 기반 클라이언트 검색으로 동작하지만, 한국어 형태소 분석이 되지 않아 한글 검색 품질이 매우 떨어짐.

**5. 프론트매터 불일치**

| 항목 | 불일치 내용 |
|------|------------|
| 날짜 형식 | 대부분 ISO 8601 (`T10:00:00+09:00`), 1개만 다른 형식 (`00:00:00 +0900`) |
| 레이아웃 필드 | 1개 글만 `layout: post` 명시, 나머지는 생략 (기본값에 의존) |
| 카테고리 형식 | 대부분 단일 값, 1개만 리스트 `[Home Lab, AI]` |

#### 프론트엔드 엔지니어 관점 개선 로드맵

**Phase 1 (1일, `_config.yml`만 수정)**:

1. `locale: "ko-KR"` 추가
2. `minimal_mistakes_skin`을 `contrast`나 `mint`로 변경
3. site description을 실제 한국어로 교체
4. 소셜 링크 URL에 실제 계정 입력
5. `timezone: "Asia/Seoul"` 설정
6. `comments: false`로 변경 (제공자 구성 전까지)

**Phase 2 (3일, 기본 커스터마이징)**:

1. `_includes/head/custom.html` 생성 → 한국어 웹폰트(Pretendard) 로드
2. `_sass/minimal-mistakes.scss` 생성 → 한국어 타이포그래피 오버라이드
3. Giscus(깃허브 기반 댓글) 연동
4. `robots.txt` 생성
5. Google Analytics 또는 Plausible 도입

**Phase 3 (1주, 고도화)**:

1. 다크모드 지원 (`prefers-color-scheme` 또는 토글)
2. OG 이미지 자동 생성 파이프라인
3. 포스트 내 코드 복사 버튼 활성화 (`enable_copy_code_button: true`)
4. 커스텀 404 페이지 디자인
5. 파비콘 및 Apple Touch Icon 추가

## 2. 시니어 웹 디자이너 관점

### 총평: 비주얼 아이덴티티 0점. '블로그'가 아니라 '테마 데모 페이지'

#### 현재 상태: Stock Theme = Zero Identity

| 디자인 요소 | 현재 상태 | 점수 |
|------------|----------|------|
| 브랜드 컬러 | 없음 (default 스킨 = 회색 팔레트) | 2/10 |
| 타이포그래피 | 시스템 폰트 기본값, 한국어 고려 없음 | 3/10 |
| 비주얼 리듬 | 단조로움. 텍스트+코드블록만 있는 평면 구조 | 3/10 |
| 다크모드 | 없음 | 0/10 |
| 파비콘 | 없음 | 0/10 |
| About 페이지 | Lorem Ipsum (라틴어 더미 텍스트) | 0/10 |
| 프로필 일관성 | 곰 캐릭터 아바타는 있으나, 이를 활용한 디자인 요소 없음 | 2/10 |

#### 핵심 디자인 진단

**1. "MM"이라는 사이트 타이틀이 모든 것을 말해줌**

사이트 제목이 "MM" (Minimal Mistakes의 약자인 듯). 이건 블로그 작성자의 정체성이 아니라 테마 이름에 가까움. 방문자가 헤더를 봤을 때 "이 사이트가 누구의 블로그인지"를 1초 안에 파악할 수 있어야 함.

**2. 한국어 타이포그래피 방치**

현재 폰트 스택:

```css
-apple-system, BlinkMacSystemFont, "Roboto", "Segoe UI", ...
```

이 폰트 스택은 라틴 문자에는 최적화되어 있지만, 한국어 환경에서는 플랫폼마다 다른 폰트로 렌더링됨:

- macOS: Apple SD Gothic Neo
- Windows: 맑은 고딕
- Android: Noto Sans CJK

2026년에 Pretendard를 쓰지 않는 한국어 테크 블로그는 진지하게 없다고 봐도 됨. 특히 iOS 개발자를 표방한다면 타이포그래피에 대한 감각이 보여야 함.

**3. 콘텐츠에 이미지가 0개**

12개 글 전체에 삽입된 이미지가 단 한 장도 없음. 텍스트와 코드 블록만 있는 긴 스크롤. 이건 읽는 사람에게 상당한 피로감을 줌.

- 홈서버 구축기 → 맥미니 실물 사진, PM2 대시보드 스크린샷이 있어야 함
- AI 모델 비교 → 벤치마크 결과 차트, 가격 비교표 이미지가 필요
- Git Worktree 설명 → 다이어그램이 필수

**4. About 페이지가 Lorem Ipsum**

이건 디자인 문제를 넘어 신뢰도 문제. 누구나 "About"을 클릭해보고 그 사람이 누구인지 확인함. 그런데 라틴어 더미 텍스트가 나오면, 그 즉시 "이 사람은 블로그를 진지하게 하지 않는구나"라고 판단함.

**5. 다크모드 부재**

2026년 기준, 테크 블로그에 다크모드가 없다는 건 선택이 아니라 누락. 개발자의 70% 이상이 다크모드를 선호함. Minimal Mistakes는 `dark`, `neon` 스킨을 기본 제공하며, `_config.yml` 한 줄로 전환 가능.

#### 디자이너 관점 개선 로드맵

**Phase 1 — 정체성 확립 (1일)**:

```
사이트 타이틀: "MM" → "Bongjin Lee" 또는 "이봉진의 기술 노트"
스킨: default → contrast 또는 dark (즉시 분위기 전환)
바이오: 현재 내용 유지하되 줄바꿈 정리
```

**Phase 2 — 타이포그래피 (2일)**:

```scss
// _sass/minimal-mistakes.scss
@import url('https://cdn.jsdelivr.net/gh/orioncactus/pretendard/dist/web/static/pretendard.css');

body {
  font-family: "Pretendard", -apple-system, BlinkMacSystemFont, system-ui, sans-serif;
  word-break: keep-all;    // 한국어 단어 단위 줄바꿈
  line-break: strict;      // 한국어 금칙처리
  letter-spacing: -0.01em; // 가독성 미세 조정
}
```

**Phase 3 — 비주얼 레이어 (1주)**:

1. 포스트 헤더 이미지 / OG 이미지 도입
2. 각 글에 최소 1-2개 스크린샷/다이어그램 추가
3. 다크모드 토글 구현
4. 파비콘 및 Apple Touch Icon 제작 (곰 캐릭터 활용)
5. 홈페이지에 히어로 영역 또는 인사말 추가

#### 테크 블로거 관점 방향 제언

**1. 니치 포지셔닝 강화**

현재 이 블로그의 가장 큰 강점은 "iOS 개발자가 AI/인프라를 배우는 과정"이라는 독특한 시점. 이 시점은 한국어 테크 블로그 생태계에서 유일무이.

- 현재 강점: iOS 개발자 → 홈랩/AI 에이전트 확장
- 유일성: 7년차 iOS 개발자의 서버/AI 실전 경험담
- 현재 약점: iOS/Swift 관련 글이 전무. 본업 이야기가 없음

권장 콘텐츠 믹스:

| 비율 | 카테고리 | 예시 |
|------|---------|------|
| 40% | AI 도구 실전 활용 | Claude Code 워크플로우, 에이전트 자동화 |
| 25% | 홈랩/인프라 구축기 | 맥미니 서버 운영, 자동매매 시스템 |
| 20% | iOS/Swift 개발 | 본업 지식 공유, 이것이 가장 신뢰도를 높임 |
| 15% | AI 산업 분석 | 트렌드 분석 (현재 4월 집중 영역) |

**2. 시리즈화 전략**

현재 Nanobot 2편이 유일한 시리즈. 하지만 글 간의 연결이 약함:

| 제안 시리즈 | 구성 | 근거 |
|------------|------|------|
| 홈랩 구축기 | 맥미니 선택 → PM2 → SSH/tmux → Nanobot → 관제탑 → (다음: 모니터링) | 기존 6개 글이 이미 시리즈 |
| AI 에이전트 실전기 | Claude Skill → RAG → 멀티모델 전략 → (다음: 실전 프로젝트) | 기존 4개 글로 구성 가능 |
| 개발자의 AI 도구 선택 | Claude vs ChatGPT → 오픈소스 AI → (다음: 로컬 LLM 구축) | 4월 글들을 시리즈로 재구성 |

**3. 글쓰기 퀄리티 한 단계 올리기**

현재 글의 구어체 톤은 장점이지만, 몇 가지 보완이 필요:

- 1차 소스 인용 습관화: Reddit 댓글만 인용하지 말고, 공식 문서, 논문, 실제 코드를 직접 확인하고 인용

## 4. 시니어 인사 전문가 관점

### 총평: 기술 역량은 보이나, 포트폴리오로서의 완성도는 20점대. "아직 준비 중"이라는 인상.

#### 채용 담당자가 이 블로그를 방문했을 때의 시나리오

**30초 스캔 결과**:

> "이력서에 블로그 링크가 있네. 들어가보자. MM? 뭘까. 포스트 목록이 보이네. AI 관련 글이 많다. About을 클릭해보자. ... 라틴어? 이건 더미 텍스트잖아. GitHub 링크를 클릭해보자. ... github.com의 메인 페이지로 이동하네. 아, 아직 프로필 설정을 안 했구나. 이 사람, 블로그를 얼마나 진지하게 하고 있지?"

채용 담당자는 블로그에 30초~2분을 씀. 그 시간 안에 전달되어야 할 메시지가 전달되지 않으면, 다음 이력서로 넘어감.

#### 포트폴리오로서의 진단

| 항목 | 현재 상태 | 채용 담당자에게 주는 인상 | 점수 |
|------|----------|------------------------|------|
| About 페이지 | Lorem Ipsum | "준비 안 됨" | 0/10 |
| 소셜 링크 | 모두 루트 URL | "존재감 없음" | 0/10 |
| GitHub 링크 | github.com/ | "계정 공유 안 함" | 0/10 |
| 이력서/포트폴리오 | 없음 | "경력 증빙 불가" | 0/10 |
| 사이트 설명 | Jekyll 기본 템플릿 텍스트 | "관리 안 됨" | 0/10 |
| 바이오 | "iOS Engineer / Swift / Flutter / Web / Home Lab / Claude Code / AI" | "관심사는 많지만 집중이 안 보임" | 5/10 |
| 글 퀄리티 | 구조적, 실전적, 읽기 좋음 | "기술적 사고력이 있음" | 7/10 |

| 포스팅 빈도 | 3월 공백 | "지속력 의문" | 4/10 |

#### 인사 전문가가 보는 치명적 3가지

**1. "이 사람이 뭘 하는 사람인지 모르겠다"**

바이오에 나열된 키워드: iOS, Swift, Flutter, Web, Home Lab, Claude Code, AI

이건 "나 이것저것 다 해봤어요"와 같음. 채용 담당자가 찾는 건 한 가지를 깊게 하는 사람. 7년차 iOS 개발자라면, iOS/Swift가 중심이고 나머지는 확장 역량으로 포지셔닝해야 함.

권장 바이오 구조:

```
"7년차 iOS 엔지니어. Swift/SwiftUI로 앱을 만들고,
홈랩에서 AI 에이전트를 굴립니다.
실전에서 겪은 문제와 해결을 기록합니다."
```

**2. "About 페이지가 없으면 포트폴리오가 아니다"**

현재 About 페이지는 Lorem Ipsum. 이건 이력서의 자기소개란을 공란으로 두는 것과 같음.

About 페이지에 반드시 포함되어야 할 내용:

1. 간단한 자기소개 (2-3문장)
2. 핵심 역량 (iOS/Swift 7년, AI 도구 활용, 홈랩 인프라)
3. 현재 관심사 (AI 에이전트 자동화, 멀티모델 전략)
4. 연락처 (이메일, GitHub, LinkedIn)
5. 경력 요약 (선택사항)

**3. "소셜 링크가 전부 빈 껍데기다"**

```
Twitter:   https://twitter.com/      → (아이디 없음)
GitHub:    https://github.com/       → (아이디 없음)
Instagram: https://instagram.com/    → (아이디 없음)
Website:   https://                  → (URL 없음)
```

채용 담당자가 GitHub를 보고 싶은데, GitHub 메인 페이지로 이동함. 이건 포트폴리오를 제출하지 않은 것과 같음.

#### 구직자 포트폴리오 전략

**단계별 우선순위 (긴급도 순)**:

**1순위 — 오늘 당장 (1시간 이내)**:

1. `_config.yml` 소셜 링크에 실제 계정 URL 입력
2. About 페이지에 자기소개 작성 (완벽하지 않아도 됨, 있어야 함)
3. site description을 실제 한국어로 교체
4. `github_username`을 실제 아이디로 변경

**2순위 — 이번 주 내**:

1. 사이트 타이틀을 "Bongjin Lee" 또는 실명 기반으로 변경
2. GitHub 프로필을 블로그와 연동 (README.md, pinned repos)
3. LinkedIn 프로필 정리 (있는 경우)
4. 바이오를 한 문장으로 정제

**3순위 — 이번 달 내**:

1. iOS/Swift 관련 글 1-2편 작성 (본업 역량 어필)
2. 포트폴리오/프로젝트 페이지 추가
3. 이력서 페이지 또는 PDF 링크 추가
4. 정기 포스팅 리듬 확립 (주 1회 또는 격주 1회)

#### 포지셔닝 제안

현재 이 블로그가 가진 가장 강력한 포지셔닝은 "AI 네이티브 iOS 개발자".

한국어 테크 블로그 생태계에서:
- iOS 개발 블로그: 많음 (but 대부분 기초 튜토리얼)
- AI/LLM 분석 블로그: 많음 (but 대부분 뉴스 번역)
- 홈랩 + AI 에이전트 + iOS 개발자의 실전기: 거의 없음

이 교집합이 이 블로그의 차별화 포인트. 이것을 About, 바이오, 글 주제에서 일관되게 어필해야 함.
