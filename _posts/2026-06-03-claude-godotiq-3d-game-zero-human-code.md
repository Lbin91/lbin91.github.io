AI가 게임을 만든다는 말은 2024년부터 끊임없이 들려왔다. 하지만 대부분은 텍스트 기반 퍼즐이거나, 인간이 뼈대를 세우고 AI가 살을 붙이는 방식이었다. 2026년 6월, Reddit r/ClaudeCode에 올라온 한 포스트가 그 한계를 깔끔하게 넘어섰다.

개발자 jf_nash이 공개한 **Marble Gauntlet**은 물리 엔진, 카메라 시스템, 메뉴, 사운드까지 포함한 3D 플랫폼 게임이다. 인간이 작성한 코드는 0줄. 인간이 배치한 노드도 0개. Claude가 MCP 도구 godotiq를 통해 Godot 엔진을 직접 조작해 완성한 결과물이다.

## 시각 없는 에이전트의 오랜 한계

게임 엔진에서 AI가 겪는 가장 큰 문제는 "눈이 없다"는 것이다. Claude는 코드를 읽고 쓸 수 있지만, 화면에 렌더링된 결과를 볼 수 없다. 좌표를 추측해서 오브젝트를 배치하고, 물리 값을 감으로 설정한다. 결과는 대부분 엉망이었다. 캐릭터가 하늘로 날아가거나, 바닥이 없어 무한 낙하하거나, 카메라가 장면 밖을 바라보는 식이었다.

이 문제를 해결하려는 시도는 있었다. GPT-4 시절부터 Unity 플러그인, Unreal 스크립트 생성 등 다양한 접근이 시도됐지만, 핵심 병목—"에이전트가 결과를 볼 수 없다"—는 해결되지 않았다. 시각 피드백 루프가 없으면 에이전트는 매번 새로운 추측을 할 뿐, 이전 시도에서 학습하지 못한다.

## Godotiq가 바꾼 것: MCP 기반 시각 피드백

godotiq는 Godot 엔진을 위한 MCP(Model Context Protocol) 서버다. Claude가 Godot 에디터와 직접 소통할 수 있게 해준다. 핵심은 스크린샷 캡처 기능이다. Claude가 씬을 수정한 뒤 스크린샷을 요청하고, 결과 이미지를 분석해 다음 수정 방향을 결정한다. 시각 피드백 루프가 닫힌 것이다.

```
# godotiq MCP의 핵심 워크플로우
1. Claude → godotiq: 노드 생성/수정 요청
2. godotiq → Godot: 씬 트리 조작
3. Claude → godotiq: 스크린샷 요청
4. godotiq → Claude: 렌더링된 이미지 반환
5. Claude: 시각 분석 → 다음 수정 결정
```

Marble Gauntlet 개발 과정에서 Claude는 이 루프를 수십 번 반복했다. 대리석의 물리 재질을 조정하고, 플랫폼 간 간격을 시각적으로 확인하며, 카메라 앵글이 플레이어 시점을 제대로 잡는지 검증했다. 각 반복에서 에이전트는 이전 결과를 "보고" 개선했다. 맹목적 좌표 추측이 아닌, 시각 검증 기반 개발로 전환된 것이다.

## 완성된 게임, 그리고 의미

결과물은 2개의 완성된 레벨을 가진 플랫폼 게임이다. 대리석을 굴려 장애물을 피해 골인하는 클래식한 메커니즘이다. 하지만 중요한 건 장르가 아니다. 인간이 단 한 줄의 코드도, 단 한 개의 노드도 직접 다루지 않았다는 점이다.

기존 "AI가 게임을 만들었다"는 프로젝트와의 차이는 명확하다. 대부분은 인간이 프롬프트를 정교하게 설계하고, 코드를 검토하고, 오류를 수정하는 과정을 거쳤다. 인간의 개입이 "도움"이 아니라 "필수 전제"였다. Marble Gauntlet은 이 전제를 제거했다. Claude가 기획하고, 구현하고, 테스트하고, 수정하는 전체 사이클을 스스로 완성한 것이다.

## 왜 지금 주목해야 하나

이 사례가 시사하는 바는 게임 개발을 넘어선다. MCP 기반 시각 피드백은 게임 엔진뿐 아니라 모든 GUI 환경에 적용 가능한 패러다임이다. 웹 개발, 데이터 시각화, UI 디자인—에이전트가 "결과를 보고" 개선하는 루프가 닫히면, 자율성은 극적으로 높아진다.

동시에 한계도 뚜렷하다. 2개 레벨의 플랫폼 게임은 데모 수준이다. 복잡한 게임 로직, 멀티플레이어, 콘솔 포팅 같은 영역으로 확장하려면 에이전트의 추론 능력과 MCP 도구의 성숙도가 모두 더 필요하다. 시각 피드백이 해결한 건 "배치와 물리" 문제지, "재미와 게임 디자인" 문제가 아니다.

하지만 방향은 명확하다. 2024년에는 AI가 텍스트를 썼다. 2025년에는 AI가 코드를 썼다. 2026년, AI가 시각 피드백을 통해 3D 세계를 직접 조작하기 시작했다. 다음 단계는 무엇이 될 것인가.

## 정리

Claude + godotiq의 Marble Gauntlet은 AI 자율 개발의 새로운 기준점을 세웠다. "인간이 도와주는 AI 개발"이 아니라 "AI가 스스로 완성하는 개발"의 실제 사례다. MCP라는 표준화된 인터페이스 덕분에 이 패턴은 다른 엔진과 도구로 빠르게 확산할 가능성이 높다.

물론 아직은 초기다. 데모를 넘어 상용 품질에 도달하려면 시간이 걸릴 것이다. 하지만 "에이전트가 게임 화면을 볼 수 없다"는 가장 큰 장벽이 무너졌다는 사실만으로도, 이 포스트는 2026년 AI 개발 역사에서 중요한 분기점으로 기억될 것이다.
