r/LocalLLaMA에서 llama.cpp의 Multi-Token Prediction(MTP) 지원이 베타에 진입했다는 발표가 371업보트, 178개 댓글을 기록했다.

## MTP가 바꾸는 것

MTP는 한 번에 여러 토큰을 예측해 생성 속도를 높이는 기법이다. DeepSeek가 V3에서 도입해 주목받았는데, 이제 llama.cpp에서도 사용 가능하다. 베타이지만 "실제로 머지될 가능성이 높다"는 평가다. 실제 속도 향상은 모델과 하드웨어에 따라 다르지만, 로컬 추론의 병목인 생성 속도를 개선하는 의미 있는 진전이다.

## AMD Strix Halo, 192GB로 갱신

같은 날 AMD Strix Halo 리프레시가 192GB 메모리를 탑재한다는 소식이 364업보트, 135개 댓글을 기록했다. 기존 128GB에서 50% 증가. 192GB면 Qwen 3.6 35B-A3B를 넉넉히 로드하고도 남는다. "이미 Strix Halo 미니폼을 샀는데, 리프레시 소식이 흥미롭지 않다"는 반응도 있었지만, 192GB는 로컬 LLM 사용자에게 분명한 이정표다.

## Gemma 4 GGUF 채팅 템플릿 수정

Gemma 4 GGUF의 채팅 템플릿이 며칠 전 수정됐다. "Gemma 4 GGUF를 업데이트할 때"라는 글이 313업보트를 받았다. 기존 템플릿 오류로 인해 일부 환경에서 출력 품질이 저하됐던 문제가 해결된 것이다.

## "오픈소스 모델이 Cursor·OpenCode의 미래다"

Cursor Enterprise에서 GPT-5.5와 Claude Opus 4.6-thinking에 프롬프트 2개로 $10를 태웠다는 경험담이 135업보트를 기록했다. 전월 $80 소모와 비교해 단가가 급등했다는 것. 같은 사용자가 Qwen 3.6 35B-A3B의 클라우드 호스팅 비용을 문의하며 124업보트를 받았다. 오픈소스 로컬/클라우드 모델로의 전환이 비용 압박에서 현실적 대안이 되고 있다.

## Qwen 3.6 27B, GPT 5.5와 Opus 4.7이 놓친 버그 발견

"쓸수록 인상적이다" — Qwen 3.6 27B가 Codex GPT 5.5와 Claude Opus 4.7이 모두 놓친 크리티컬 버그를 발견했다는 글이 66업보트, 71개 댓글을 받았다. GPT 5.5와 Claude는 자신의 답을 끝까지 고수했지만, 로컬 모델이 정확히 짚어냈다. 물론 단일 사례이지만, 로컬 모델의 품질이 상용 모델과 동등한 수준에 근접하고 있다는 실증이다.

## 백악관, AI 모델 사전 심사 검토

백악관이 AI 모델 출시 전 사전 심사(vetting)를 검토 중이라는 보도가 49업보트, 54개 댓글을 기록했다. 오픈웨이트 생태계에 대한 규제 가능성으로 커뮤니티의 우려가 크다.

## 시사점

로컬 LLM 인프라가 소프트웨어(llama.cpp MTP)와 하드웨어(AMD 192GB) 양쪽에서 동시에 진화하고 있다. 상용 API 비용 상승과 모델 품질 불안정이 로컬 전환을 가속하는 가운데, 오픈소스 모델의 품질이 상용 수준에 근접하며 실질적 대안이 되고 있다.
