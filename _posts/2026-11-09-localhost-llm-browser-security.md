r/LocalLLM에 이런 글이 올라왔다. 브라우저에서 열어둔 웹사이트가 사용자의 로컬 LLM 서버에 접근할 수 있다는 얘기다. 작성자 본인도 "아마 옛날 얘기겠지만"이라고 말문을 열었는데, 그 '옛날 얘기'가 357포인트를 받으며 다시 화제가 됐다. 이미 아는 사람에겐 지루한 상식이고, 모르는 사람에겐 꽤 뼈아픈 이야기. 나는 후자에 가까웠다.

## localhost라는 착각

로컬에서 Ollama나 LM Studio를 돌리면 서버는 127.0.0.1에서 귀를 기울인다. 외부 인터넷에서는 접근이 안 되니까 안전하다. 여기까진 맞다. 문제는 외부가 아니라는 점이다. 브라우저 탭 안에서 실행되는 자바스크립트는 웹페이지가 어디에 호스팅돼 있든 내 컴퓨터의 loopback 주소로 요청을 보낼 수 있다.

실제로 이런 코드가 동작한다.

```js
// 내가 방문한 사이트에서 돌아가는 코드
const res = await fetch("http://127.0.0.1:11434/api/tags");
const { models } = await res.json();
console.log(models); // 내가 설치한 모델 목록 그대로
```

기본 포트만 알면 설치된 모델을 열람하고 프롬프트를 마음대로 보낼 수 있다. RAG로 개인 문서를 붙여둔 구성이라면 상황이 더 곤란하다. 모델에게 "홈 디렉터리 문서 요약해줘"를 시키고 응답을 받아내는 식으로 내 파일이 바깥으로 새어나갈 수 있다. 예전부터 알려진 DNS 리바인딩 기법을 쓰면 사설 IP 대역 접근 제한마저 우회하는 사례들이 있었다.

브라우저 쪽에서도 Private Network Access 같은 제한을 점차 강화하고 있지만 아직 완벽한 경계가 아니다. 그래서 결국 서버 쪽 방어가 남는다.

## 서버 쪽에서 막는 방법

의외로 할 일이 많지 않다.

- 바인딩 주소부터 확인한다. 0.0.0.0으로 열어뒀다면 집 공유기 안에 갇혀 있어도 LAN 전체에 노출된다. 필요 없으면 127.0.0.1을 유지한다.
- CORS 오리진은 화이트리스트로 좁힌다. Ollama라면 환경변수 하나로 끝난다.

```bash
OLLAMA_ORIGINS="http://localhost:3000" ollama serve
```

- 웹 UI 없이 API만 쓴다면 아예 오리진 허용을 끄는 편이 낫다.
- 브라우저에서 접근해야 하는 구성이라면 nginx 같은 리버스 프록시에 토큰 인증을 붙인다. 모델 서버 자체에는 인증이 없는 경우가 많아서 프록시 뒤에 두는 게 현실적이다.
- 상시 구동 서버라면 방화벽에서 11434 같은 포트를 외부로 열지 않았는지 한 번쯤 짚어본다.

설정 몇 줄이면 되는 일인데도 기본값으로 방치해둔 서버가 의외로 흔하다. 기본값은 편의를 위한 것이라 보안을 위한 게 아니라서다.

## 왜 다시 주목하나

로컬 LLM 사용자층이 달라졌다. 예전엔 취미로 몇 명이 만져보던 게 이제는 집 서버나 워크스테이에 상시로 돌리고, 개인 문서와 메모를 컨텍스트로 넘기는 구성이 흔해졌다. 서버가 알게 모르게 민감한 걸 읽는 시대가 됐는데, 그 경계를 가장 쉽게 넘는 도구가 하필 브라우저다. 매일 수십 개 탭을 띄워놓고 사는 사람 입장에선 공격면이 하나둘이 아니다.

재미있는 건 커뮤니티 반응이었다. "이미 알고 있던 얘기"라는 말이 댓글에 깔려 있었는데, 그렇다면 왜 357포인트였을까. 알고 있다고 믿었던 지식이 실제로는 잘 안 보이고 있었다는 증거에 가깝다. 나부터 그랬다. 공유되는 경각심은 늘 새로운 누군가에게 처음 도착한다.

## 정리

잘 알려진 취약점이라는 사실은 안전의 증거가 아니다. 알려졌다고 다들 고쳤다는 뜻도 아니고. 세 가지만 확인해두자. 서버가 loopback에만 바인딩돼 있는지, CORS가 열려 있다면 누구에게 열어뒀는지, 브라우저가 최신인지. 로컬 모델을 상시 돌리는 사람이라면 오늘 점심먹고 나서라도 설정 화면을 한 번 열어볼 만하다.
