Claude Code로 새 세션을 열었다. 아무것도 시키지 않았다. 질문도, 코드도, 파일 하나 건네지 않았는데 `/context all`을 돌려보니 35,000개 토큰이 이미 로드되어 있었다.

r/ClaudeCode에 이 경험이 올라왔다. u/LorenzoSith라는 사용자가 정리한 글인데, 읽으면서 계속 고개가 끄덕여졌다. 나도 비슷한 상황을 겪었으니까. 설정 파일 몇 개, 스킬 몇 개, MCP 서버 몇 개 넣어두면 어느새 컨텍스트 윈도우의 상당 부분이 잠식당한다. 모델이 좋아질수록 컨텍스트를 더 많이 쓸 수 있게 됐지만, 그렇다고 낭비를 방치해도 된다는 뜻은 아니다.

## 35K의 구성

시작 토큰이 어디서 오는지 들여다보면 패턴이 보인다. 시스템 프롬프트, 시스템 도구, 등록된 스킬, CLAUDE.md 같은 메모리 파일. 하나하나는 작아 보이지만 쌓이면 무시할 수 없는 볼륨이 된다.

가장 큰 범인은 의외로 시스템 도구였다고 한다. DesignSync, Artifacts, Dynamic Workflows 같은 기능들. 쓰지는 않는데 컨텍스트에는 계속 자리를 차지하고 있었다. 스킬도 마찬가지다. 프로젝트마다 다른 절차를 스킬로 만들어두면 편리하지만, 사용하지 않는 스킬의 설명文本이 매 세션마다 로드되는 건 순수한 낭비다.

MCP 서버도 한몫한다. 도구 스키마 자체가 꽤 부피가 크다. 최신 Claude Code는 도구 검색(tool search)을 통해 MCP 스키마를 지연 로딩할 수 있게 됐다고는 하지만, 서버 자체를 띄워두면 그에 따른 기본 비용이 발생한다.

## 무엇을 덜어냈는가

Lorenzo의 접근은 단순했다. 가장 큰 것부터 잡는다.

CLAUDE.md는 프로젝트별 핵심 정보와 자주 발생하는 함정만 남겼다. 워크플로우나 절차성 내용은 필요할 때 로드하는 스킬로 옮겼다. 쓰지 않는 스킬은 삭제하고, 수동으로만 트리거하고 싶은 것은 사용자 호출 전용으로 설정해서 일반 스킬 목록에서 보이지 않게 만들었다. MCP 서버도 실제로 사용하는 것만 남기고 전부 잘라냈다.

결과는 13K. 약 63% 감소. 정확한 숫자는 설정마다 다르겠지만, 접근 방식 자체는 누구나 적용할 수 있다.

## 댓글에서 밝혀진 더 큰 문제

이 글의 댓글이 사실 더 흥미롭다. u/Lexeik이라는 사용자가 자기 MCP 서버를 직접 측정해본 결과를 공유했는데, 44KB 중 26KB가 `outputSchema`였다. 모델이 읽지도 않는 스키마 정의가 순수 비용으로 자리잡고 있었다는 뜻이다.

더 심각한 건 응답 중복이다. MCP 사양이 호환성을 위해 구조화된 콘텐츠와 텍스트 양쪽에 같은 JSON을 넣기를 권장하는데, 이러면 서버가 반환하는 모든 응답이 조용히 두 배가 된다. `/context all`에는 잡히지 않는 숨은 비용이다. 세션이 진행될수록 누적되고, 정작 사용자는 컨텍스트가 왜 이렇게 빨리 차는지 체감하지 못한다.

Lexeik의 해결책은 응답 본문에 크기 제한을 두고, 전체 데이터가 필요할 때만 별도 도구로 가져오게 만드는 것이었다. 텍스트 부분에는 JSON 대신 짧은 인간 가독용 요약을 넣었다. 사양이 바뀌지 않는 이상 서버 작성자가 의도적으로 결정해야 하는 부분이다.

## 왜 이게 중요한가

컨텍스트 윈도우가 200K, 500K로 커지고 있으니 토큰 몇 만 개쯤은 신경 안 써도 되지 않을까? 그렇게 생각할 수 있다. 하지만 컨텍스트가 커질수록 모델의注意力 분산 문제도 함께 커진다. 200K 컨텍스트에서 35K의 잡음이 섞여 있으면, 정작 중요한 사용자 요청이 묻힐 가능성이 높아진다. 연구 결과들도 긴 컨텍스트에서 모델 성능이 저하된다는 걸 계속 보여주고 있다.

비용 문제도 있다. API 호출 기반이라면 토큰 수가 곧 비용이다. 매 세션마다 22K 토큰을 추가로 보내는 건, 하루에 열 번 세션을 열면 220K 토큰의 낭비로 이어진다. 한 달이면 꽤 의미 있는 금액이 된다.

그리고 실용적인 측면이 있다. 깔끔한 컨텍스트는 응답 품질로 이어진다. 모델이 불필요한 정보에 방해받지 않고, 사용자의 의도에 집중할 수 있다. Lorenzo가 13K로 줄인 뒤 체감한 가장 큰 변화는 비용 절감이 아니라 응답의 정확도 향상이었다고 한다.

## 정리하자면

새 Claude Code 세션을 열고 `/context all`을 한 번 실행해보라. 숫자가 생각보다 크다면, 뭔가 덜어낼 여지가 있다는 뜻이다. 쓰지 않는 도구를 끄고, 스킬을 정리하고, MCP 서버를 검토하는 것만으로도 체감 차이가 난다.

컨텍스트 윈도우는 모델의 작업 공간이다. 작업 공간이 어수선하면 누구든 집중력이 떨어진다. 모델이라고 다르지 않다.
