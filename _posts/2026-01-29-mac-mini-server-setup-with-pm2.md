7년차 iOS 개발자가 백엔드 초보의 시선으로, 맥미니 홈서버에 PM2를 도입하며 겪은 시행착오를 공유합니다.

## 들어가며: iOS 개발자의 서버 도전기

평소 개인 SaaS 프로젝트를 위해 서버가 필요했습니다. 클라우드 서비스를 쓸 수도 있지만, 직접 서버를 굴려보고 싶은 호기심에 맥미니를 중고로 구매했습니다. 저전력에 성능도 좋고, 무엇보다 macOS 환경이라 익숙하니까요.

iOS 개발만 7년 하다 보니 서버 쪽은 완전 초보입니다. 그래서 이 글은 "나처럼 백엔드가 낯선 분들"을 위해 최대한 쉽게 풀어보려 합니다.

## 첫 번째 시도: 그냥 node 실행

설레는 마음으로 터미널을 열고 서버를 실행했습니다.

```bash
$ node server.js
Server running on port 3000...
```

잘 돌아갑니다. "어, 생각보다 쉽네?" 싶었습니다.

그런데 며칠 운영해보니 현실의 벽에 부딪혔습니다.

1.  **터미널을 닫으면 서버도 죽는다**: 당연한 건데 처음엔 몰랐습니다. `nohup`이라는 명령어로 백그라운드 실행이 가능하다는 것도 나중에 알았는데, 로그 관리가 번거롭더군요.
2.  **밖에서 상태 확인이 어렵다**: 카페에서 작업하다가 "서버 살아있나?" 궁금해도 확인할 방법이 마땅치 않았습니다.
3.  **에러나면 그냥 죽어있다**: 예기치 않은 에러로 프로세스가 종료되면, 집에 가서 다시 켜줄 때까지 서비스는 다운 상태입니다.

iOS 개발할 때는 Xcode가 크래시 로그도 보여주고, TestFlight로 배포 상태도 확인할 수 있는데... 서버는 이런 게 없나? 분명 있을 텐데?

검색 끝에 **PM2(Process Manager 2)** 라는 도구를 발견했습니다.

## PM2란?

PM2는 Node.js 프로세스를 관리해주는 도구입니다.

iOS 개발로 비유하자면, Xcode의 Instruments + 크래시 리포터 + 자동 재시작 기능을 합쳐놓은 느낌이랄까요. 서버가 죽으면 알아서 다시 켜주고, 로그도 깔끔하게 관리해줍니다.

## 설치 및 설정 과정

Node.js와 npm이 설치되어 있다면, PM2 설치는 한 줄이면 됩니다.

### 1. PM2 설치

```bash
npm install pm2 -g
```

### 2. 서버 실행

기존 `node server.js` 대신 `pm2`로 실행합니다. `--name` 옵션으로 이름을 붙여두면 나중에 관리하기 편합니다.

```bash
pm2 start server.js --name "my-server"
```

실행하면 터미널이 바로 돌아옵니다. 백그라운드에서 알아서 돌고 있는 거죠.

### 3. 자주 쓰는 명령어

처음에 명령어가 많아 보여서 겁났는데, 실제로 쓰는 건 몇 개 안 됩니다.

```bash
# 실행 중인 프로세스 목록 확인
pm2 list

# 로그 보기 (실시간으로 계속 출력됨)
pm2 logs

# 특정 서버 로그만 보기
pm2 logs my-server

# 최근 100줄 로그 확인
pm2 logs --lines 100

# 서버 재시작 (코드 수정 반영 시 사용)
pm2 restart my-server

# 서버 중지
pm2 stop my-server

# 서버 삭제 (PM2 리스트에서 제거)
pm2 delete my-server

# CPU/메모리 모니터링 (시각적으로 예쁘게 보여줌)
pm2 monit
```

`pm2 monit` 화면은 처음 보면 감탄이 나옵니다. 터미널에서 이런 대시보드가 가능하구나 싶었어요.

### 4. 재부팅해도 자동 실행되게 설정

이 부분이 제일 중요했습니다. 맥미니가 재부팅되면 서버도 자동으로 켜져야 하니까요.

```bash
# 1. 스타트업 스크립트 생성
pm2 startup

# 2. 터미널에 출력되는 명령어를 복사해서 그대로 실행
#    (sudo env PATH=... 형태의 긴 명령어가 나옵니다)

# 3. 현재 실행 중인 프로세스 목록 저장
pm2 save
```

이렇게 해두면 정전이 되든, macOS 업데이트로 재시작되든, 알아서 서버가 살아납니다.

## 마치며

PM2 도입 후 달라진 점을 정리하면:

| 이전 | 이후 |
|------|------|
| 터미널 닫으면 서버 종료 | 백그라운드에서 계속 실행 |
| 에러 나면 그냥 죽어있음 | 자동 재시작 |
| 로그 확인 어려움 | `pm2 logs`로 간편하게 |
| 재부팅하면 수동 실행 | 자동 복구 |

솔직히 백엔드 초보 입장에서 PM2 없이 서버 운영하는 건 상상이 안 됩니다.

iOS 개발할 때 Crashlytics나 Firebase 같은 모니터링 도구 없이 앱 운영하는 느낌이랄까요. 물론 고수분들은 Docker나 Kubernetes 같은 더 전문적인 도구를 쓰시겠지만, 저처럼 홈서버로 작은 SaaS를 돌리는 수준에서는 PM2로 충분하다고 느꼈습니다.
