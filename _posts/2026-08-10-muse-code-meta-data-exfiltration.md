AI 코딩 도구가 내 컴퓨터에 설치되어 있다. 그 도구가 내가 쓰는 다른 도구의 설정 파일을 읽고, 그 내용을 자기 회사 서버로 보낸다. 동의는 묻지 않았고, 끄는 방법도 불분명하다. r/ClaudeCode에서 이런 폭로가 올라왔다. Meta의 Muse Code가 그렇게 작동한다는 내용이다.

처음 읽었을 때는 좀 과장된 거 아닌가 싶었다. 기업이 경쟁사의 설정 파일을 의도적으로 수집한다? 그런데 폭로한 사용자가 독립 프라이버시 감사 프롬프트를 돌려 확인한 내용을 보면 생각이 바뀐다. 수집 범위가 상당히 구체적이다.

## 무엇이 수집되는가

Muse Code가 읽어가는 파일 목록을 보면, Claude Code 사용자라면 등이 서늘해진다.

먼저 `~/.claude/CLAUDE.md`다. Claude Code에서 프로젝트 컨텍스트, 코딩 컨벤션, 사용자 지시사항을 적어두는 파일이다. 팀의 개발 철학이 담기는 곳이다. 그다음 `settings.json`. API 키가 아닐지라도, 어떤 도구를 쓰는지, 어떤 권한을 열어뒀는지가 드러난다. 그리고 `~/.claude/projects/*.jsonl`. 세션 기록이다. 내가 Claude Code와 주고받은 대화, 내가 어떤 코드를 작성하고 어떤 문제를 겪었는지가 통째로 들어 있다.

Codex 사용자도 예외가 아니다. `~/.codex/AGENTS.md`를 똑같이 읽어간다.

이 데이터가 Meta 서버로 전송된다. 백그라운드에서, 사용자에게 알리지 않고.

## "호환성"이라는 방패

옹호하는 쪽의 논리는 예상할 수 있다. "다른 도구와의 호환성을 높이기 위해서"라는 설명이다. Claude Code 사용자가 Muse Code로 넘어올 때 매끄럽게 작동하도록, 기존 설정을 읽어서 적응한다는 이야기다. 나쁘지 않은 의도처럼 들린다.

문제는 방식이다.

호환성이 목적이라면, 사용자에게 물어봐야 한다. "기존 Claude Code 설정을 읽어오겠습니까?" 이 한 줄이면 된다. 그런데 Muse Code는 기본값을 전송 ON으로 설정했다. 옵트아웃 경로도 명확하지 않다. 사전 고지도 없다. 백그라운드에서 조용히 일어나는 일이다.

의도가 선하든 악하든, 사용자가 모르게 데이터를 가져가는 건 설계 선택의 문제다. 기본값을 ON으로 둔 것은, 투명성보다 데이터 수집을 우선했다는 뜻이다.

## 왜 이 일이 더 넓은 의미를 갖는지

이 사건이 단순히 "Muse Code 하나의 문제"로 끝나지 않는 이유는, AI 코딩 도구가 접근하는 데이터의 성질 때문이다.

생각해보자. AI 코딩 에이전트는 내 파일 시스템 전체에 접근할 수 있다. 프로젝트 소스코드, 환경 변수 파일, SSH 키가 있는 디렉토리, 다른 도구의 설정. 에이전트가 이 파일들을 읽는 건 기능적으로 필요하다. 코드를 수정하려면 코드를 봐야 하고, 컨텍스트를 이해하려면 프로젝트 구조를 파악해야 한다. 그래서 우리는 에이전트에게 파일 시스템 접근 권한을 준다.

그 권한이 외부로 데이터를 보내는 데 쓰일 때 문제가 생긴다.

에이전트가 내 컴퓨터에서 읽은 데이터를 어디로 보내는지, 사용자가 기본적으로 통제할 수 있어야 한다. 로컬에서만 쓰이는 데이터와 원격 서버로 전송되는 데이터를 구분하는 것은 최소한의 기준이다. Muse Code 사례는 이 기준이 지켜지지 않았을 때 어떤 일이 벌어지는지 보여준다.

더 우려되는 건 업계 전반의 동향이다. 한 회사가 "경쟁사 도구와의 호환성"이라는 명분으로 이런 데이터 수집을 정상화하면, 다른 회사들도 비슷한 논리를 들이댈 수 있다. Claude Code가 사용자의 VS Code 설정을 읽어와도 되는가? Cursor가 사용자의 Copilot 기록을 수집해도 되는가? 선이 그어지지 않으면, 누구도 막지 못한다.

## 정리

지금 AI 코딩 도구 시장은 기능 경쟁이 치열하다. 더 빠른 코드 생성, 더 정확한 추론, 더 긴 컨텍스트. 이런 경쟁은 환영할 일이다. 하지만 그 이면에서 각 도구가 사용자의 데이터를 어떻게 다루는지에 대한 기준은 아직 정립되지 않았다.

Muse Code가 보여준 구조 — 경쟁사 설정 파일을 읽고, 세션 기록을 수집하고, 사용자 동의 없이 메타 서버로 전송하는 구조 — 를 두고 "불편하면 다른 도구를 쓰면 된다"고 말하는 건 너무 가볍다. 사용자는 자기 데이터가 어디로 가는지 알 권리가 있고, 그 전송을 통제할 수 있어야 한다. 기본값이 투명한 동의여야 한다는 건 과한 요구가 아니다.

에이전트에게 내 컴퓨터를 열어주는 건 불가피한 선택이다. 하지만 열어준 문 너머로 누가 무엇을 가져가는지는 내가 알아야 한다. 그게 신뢰의 출발점이다.
