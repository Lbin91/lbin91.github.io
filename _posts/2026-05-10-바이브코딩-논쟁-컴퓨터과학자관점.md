r/ClaudeCode에서 "컴퓨터 과학자의 관점에서 본 바이브 코딩"이라는 글이 273업보트, 265개 댓글로 가장 뜨거운 논쟁을 기록했다.

## 무엇이 논쟁인가

작성자는 "바이브 코딩을 옹호하는 사람들이 실제로 의미 있는 것을 만들었다고 확신하지 못하겠다"며, 소프트웨어 엔지니어링의 근본적 이해 없이 LLM에만 의존하는 코딩 방식을 비판했다.

댓글은 양극단으로 갈렸다. "15년 차 개발자로서 완전히 반대다. LLM으로 지금 할 수 있는 것은 예전 도구들보다 수년 앞서 있다"는 반박이 있는가 하면, "바이브 코딩으로 만든 것을 유지보수하려고 보면 지옥"이라는 공감도 있었다.

## Claude Code, 포기 시도 실패기

"Claude Code를 포기하려 했으나 실패했다"는 글(27↑, 17💬)도 흥미롭다. 350K SLOC Go 게임 코드베이스에서 Codex로 전환을 시도했으나, "정말 Codex를 좋아하려고 했지만 결국 Claude로 돌아왔다"고 밝혔다. "Codex는 정확도가 높지만 Claude에 비해 대규모 리팩토링에서 답답하다"는 평.

## Claude Code 2.1.117, 무인 에이전트 워크플로 망가뜨려

Claude Code 업데이트가 Bash 권한 없이 Read/Glob/Grep/Edit/Write만 허용하던 무인 코드 리뷰 워크플로를 망가뜨렸다는 보고(47↑, 22💬). "Bash 없이 레포 검색은 허용하는 것이 합리적 경계선인데, 회귀로 사라졌다"는 비판. 무인 에이전트 환경에서 보안과 기능의 균형이 깨진 사례다.

## 에이전트 평가, "실행 효율 무시" 문제

r/AI_Agents에서 "대부분의 AI 에이전트 평가가 실행 효율을 완전히 무시한다"는 지적(21↑, 12💬). 완벽한 점수를 받아도 같은 도구를 여러 번 호출하고 무의미한 반복을 하는 에이전트가 많다. "데모 아래의 혼란을 숨기고 있다"는 분석.

## 포켓몬 스타일 멀티 에이전트 대시보드

Claude Code 세션을 포켓몬 테마로 관리하는 Pokegents 오픈소스 프로젝트(66↑, 9💬). 다중 코딩 에이전트 세션 관리의 UX 문제를 게임처럼 풀었다. 에이전트 세션이 늘어나는 상황에서 관리 도구의 필요성을 보여준다.

## 시사점

바이브 코딩 논쟁의 핵심은 "LLM이 코딩을 대체하는가"가 아니라 "LLM을 도구로 활용하면서 엔지니어링 기반을 유지할 수 있는가"다. 실무자들은 이미 도구 선택을 넘어 워크플로 설계 단계에 있으며, "어느 모델"보다 "어떤 방식"이 중요해지고 있다.
