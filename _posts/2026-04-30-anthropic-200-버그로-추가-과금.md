Claude Code의 버그 때문에 사용자가 200달러를 추가로 청구받았는데, Anthropic이 환불을 거부했다는 이야기가 r/claudecode에서 화제다. GitHub 이슈로 올라온 제보가 81업보트를 받으며, 커뮤니티에서 공감과 분노가 동시에 쏟아졌다.

## 무슨 일이 있었나

문제의 핵심은 Claude Code의 HERES.md 관련 버그다. 사용자가 의도하지 않았음에도 시스템이 불필요하게 토큰을 소모하면서, API 사용량이 폭증했다. 결과적으로 평소보다 200달러가 더 나온 청구서를 받게 됐다.

GitHub 이슈에 따르면, push option이나 설정 파일 파싱 과정에서 무한 루프에 가까운 토큰 소모가 발생한 것으로 보인다. 사용자 입장에서는 "내가 코딩을 많이 한 것도 아닌데 왜 이렇게 나오지" 하는 상황이다.

Anthropic에 환불을 요청했지만 거부당했다. 최첨단 AI 모델을 만드는 회사가 기본적인 정규식 수준의 문제도 해결하지 못하면서, 그 피해를 사용자에게 떠넘긴다는 비판이 커졌다.

## 커뮤니티 반응

가장 많은 추천을 받은 댓글은 실용적인 조언이었다. "신용카드 회사에 chargeback을 요청하라"는 것. 실제로 미국에서는 서비스 결함으로 인한 과다 청구에 대해 chargeback이 승인되는 경우가 많다.

다른 댓글들은 더 근본적인 문제를 지적했다. Claude Code의 과금 구조 자체가 불투명하다는 것. 사용자가 실시간으로 토큰 사용량을 모니터링할 수 있는 대시보드가 부족하고, 한도 설정 기능도 제한적이다. API 기반 과금의 고질적 문제가 사용자 경험으로 직결되는 사례다.

이후 X(트위터)에서 Anthropic 측이 환불 처리 중이라는 정보가 올라오기도 했다. GitHub 이슈가 공개적으로 화제가 되자 대응에 나선 것으로 보인다.

## Claude Code 과금의 구조적 문제

이 사건은 단순한 버그가 아니다. Claude Code의 과금 모델 자체가 가진 구조적 취약점을 보여준다.

Claude Code는 사용자가 직접 API 키를 연동하거나, Anthropic의 구독 플랜을 통해 토큰을 소모한다. 문제는 사용자가 "이 프롬프트가 얼마나 비용이 드는지"를 직관적으로 파악하기 어렵다는 것이다. 한 번의 코딩 세션에서 수십만 토큰이 소모될 수 있으며, 그 사이사이에 버그로 인한 낭비가 끼어들면 사용자는 통제력을 잃는다.

비교하면 GitHub Copilot은 정액제다. 월 10달러를 내면 쓰는 만큼 쓴다. 부하가 걸려도 추가 요금이 나오지 않는다. Cursor도 월 정액에 토큰 제한이 정해져 있다. 반면 Claude Code의 사용량 기반 과금은 "버그 하나로 200달러"가 가능한 구조다.

## 무엇을 바꿔야 하나

이 사건에서 몇 가지 개선점이 보인다.

첫째, **실시간 사용량 모니터링**이 필요하다. 세션 단위로 토큰 소모량을 실시간으로 보여주고, 설정한 임계치에 도달하면 경고를 보내야 한다.

둘째, **버그로 인한 과다 과금에 대한 자동 환불 정책**이 있어야 한다. 사용자가 일일이 이슈를 올리고 chargeback까지 가야 한다는 건 서비스 신뢰를 깎는 일이다.

셋째, **하드 리밋(hard limit) 설정**이 가능해야 한다. "하루에 10달러 이상 쓰지 마라" 같은 설정이 가능해야 버그로 인한 폭주를 막을 수 있다.

## 개발자들이 느끼는 불안

r/claudecode 최근 흐름을 보면 비용 관련 불만이 꾸준히 올라온다. "토큰 한도 초과 → 영적 성장"이라는 자조적인 글도 같은 날 105업보트를 받았다.

Claude Code의 편의성은 모두가 인정하지만, 그 편의성의 대가가 "언제 터질지 모르는 과금 폭탄"이라면 장기적인 채택에 악영향을 줄 수 있다. 특히 개인 개발자나 소규모 팀에게는 치명적이다.

## 정리

200달러 버그 과금 사건은 Claude Code의 과금 투명성과 안전장치 부족을 적나라하게 보여줬다. Anthropic이 기술적으로는 앞서가면서도, 서비스 운영 측면에서는 기본적인 사용자 보호 장치가 부족하다는 평가를 피하기 어렵다. chargeback이 해결책이 돼서는 안 된다.
