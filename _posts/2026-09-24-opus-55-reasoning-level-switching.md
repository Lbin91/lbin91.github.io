reasoning 모델을 써 본 사람이라면 한 번쯤 이런 상황을 겪는다. 대화를 시작할 때는 복잡한 문제라고 생각해 깊게 생각하는 모드로 걸어두는데, 막상 대화가 진행되니 이제는 가벼운 질문과 답이 오가는 단계다. 그런데도 모델은 건드리지 않는 한 계속 같은 깊이로 생각한다. 토큰은 토큰대로 새고, 답변은 답변대로 느리게 나온다.

Anthropic이 Opus 5.5에서 이 지점을 건드렸다. 채팅 도중에 reasoning 강도를 자유롭게 전환할 수 있게 한 것. OpenAI 쪽에서 먼저 시도한 방식에서 영감을 받았다고 공식적으로 언급했는데, 흥미로운 건 과거의 실패담이다. 이전에도 중간에 레벨을 바꾸는 건 기술적으로 가능했지만, 바꾸는 순간 오히려 초과 지불이 발생하는 구조였다. 그러니까 아무도 안 쓰는 기능이었던 셈이다.

## min-maxing이 실제로 되는가

이제 그 제약이 사라졌다. 어려운 질문에는 extra로 물고 늘어지고, 반복적인 후속 질문에는 low나 medium으로 내리는 식의 운영이 가능해졌다. r/ClaudeCode 쪽 실사용자 반응을 보면 이 지점을 바로 알아챈다. "extra로 시작해서 low/medium으로 내리는 내 워크플로에 천군만마"라는 반응이 나오는 이유다.

왜 이렇게 반응이 뜨거운가. 에이전트를 오래 돌려 본 사람은 안다. 긴 세션에서 reasoning 토큰이 전체 비용에서 차지하는 비중이 생각보다 크다. 모델이 답을 내놓는 데 쓰는 토큰보다 답하기 전에 '생각하는' 데 쓰는 토큰이 더 비싸게 붙는 경우가 흔하다. 그런데 그 생각의 깊이를 난이도에 맞춰 즉석에서 조절할 수 있다면, 이야기가 달라진다.

정리하면 이런 흐름이다.

```
복잡한 요청 → reasoning: extra → 깊게 분석
후속 질문(맥락 공유됨) → reasoning: low → 빠르고 저렴하게
단순 반복 작업 → reasoning: medium → 균형
```

코드로 보면 더 직관적이다. 에이전트 설정에서 태스크 난이도별로 다르게 거는 식이다.

```json
{
  "easy_task":  { "thinking": "low" },
  "refactor":   { "thinking": "medium" },
  "debug_hard": { "thinking": "extra" }
}
```

## 비용 구조의 변화라는 관점

이 기능을 단순한 편의 기능으로 볼 수도 있지만, 나는 비용 구조의 변화라고 본다. 지금까지 LLM 비용 최적화의 대명사는 모델 선택이었다. 큰 모델에서 작은 모델로 내려가는 것, 그러니까 라우팅. 그런데 모델 내부에서 reasoning 깊이를 다루게 되면서 최적화의 단위가 한 단계 미세해졌다. 같은 모델을 쓰면서도 태스크별로 지불 금액이 달라지는 것.

관리 입장에서도 좋다. 모델을 여러 개 왔다 갔다 하면 스타일이 흔들리고 컨텍스트 관리도 번거로워진다. 하나의 모델 안에서 다이얼만 돌리는 방식은 그 부담이 없다. 일관성과 비용 효율을 동시에 잡는 셈.

동시에 커뮤니티의 다른 흐름도 눈에 띈다. 어제 다뤘던 것처럼 로컬 진영은 단일 GPU로 Qwen 3.8 27B를 굴리며 토큰 과금 자체를 없애는 방향으로 가고 있고, 클라우드 진영은 이렇게 reasoning 깊이 조절로 같은 문제를 다른 방식으로 푼다. 문제의식은 같다 — reasoning 토큰이 너무 비싸다 — 인데, 접근이 정반대라는 점이 지금 시점의 생태계를 잘 보여준다.

## 왜 주목할까

개인적으로 이 기능이 에이전트 장기 세션에서 특히 빛을 발할 거라 본다. 사람이 하루 종일 일할 때도 어려운 문제 깊게 생각하다가 잡무는 빠르게 처리하듯, 에이전트도 이제 그런 리듬을 가질 수 있게 된 것이다. '생각의 깊이'가 드디어 조절 가능한 리소스가 됐다는 것.

물론 숙제도 있다. 어떤 요청이 어려운지 판단하는 건 여전히 사람 몫이다. 자동 판단이 어설프면 extra를 걸어야 할 곳에 low를 걸어 답변 품질이 떨어질 수 있고, 그 역도 마찬가지다. 처음에는 보수적으로, 그러니까 어려운 쪽에 두고 시작해서 점점 내리는 식이 안전할 것이다.

## 정리

Opus 5.5의 reasoning 레벨 전환은 기능 추가라기보다는 지불 모델의 변화에 가깝다. 생각을 많이 하면 비싸고, 적게 하면 싸다는 당연한 원칙이 드디어 실시간으로 조절 가능해졌다. LLM 비용 때문에 고민 중이라면, 모델을 바꾸는 것 말고 reasoning 깊이를 다이얼로 조절하는 쪽을 먼저 살펴볼 만하다.
