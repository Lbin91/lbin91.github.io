브라우저 엔진은 못 만드는 것으로 알려져 있다. Chromium, WebKit, Gecko. 수백 명의 엔지니어가 수십 년 동안 다듬어온 덩어리들이고, 새 브라우저를 만들겠다며 시작한 시도들은 대부분 결국 이 중 하나를 포크하거나 감싸는 데서 끝났다. 그런데 어제 r/ClaudeCode에 올라온 포스트는 그 전제를 흔든다. 한 사람이 몇 달에 걸쳐 Rust로 브라우저 엔진을 통째로 직접 만들었다는 이야기다.

이름부터가 정색하고 시작하지 않는다. 브라우저는 T.A.B.(Tiny Ass Browser), 엔진은 Kingmaker. 농담조 이름과 달리 안에 든 건 진짜다. 자체 JavaScript 엔진, 바이트코드 VM, JIT 컴파일러, DOM 구현, CSS 레이아웃과 페인팅 파이프라인, WebAssembly 런타임, 렌더링 스택. 브라우저를 브라우저로 만드는 부품을 전부 갖췄다. 크로미움 포크도, 일렉트론 앱도, WebView를 감싼 껍데기도 아니라고 작성자는 못 박는다.

숫자가 이어진다.

- Web Platform Tests (Testharness): 91.42%
- ECMAScript (Test262): 97.83%
- WebAssembly: 100%
- 다섯 개 스위트 통합: 92.21%

통과한 테스트 결과는 176만 건이 넘는다. 데모 페이지 몇 개 예쁘게 띄우는 수준이 아니다. 구글과 HEY, 37signals 같은 실제 사이트가 이 엔진 위에서 돌아가고, 스크린샷이 증거로 첨부되어 있다.

## 어떻게 만들었나

여기가 포스트에서 가장 흥미로운 지점이다. 개발 방식을 작성자는 셋으로 나눠 설명한다. 아키텍처와 방향은 사람이 정한다. 구현과 디버깅, 테스트는 Claude Code 에이전트에 맡긴다. 그리고 무엇이 "실제로 동작한다"고 인정할지는 Rust 컴파일러와 업스트림 준수 스위트가 결정한다.

컴파일러와 표준 테스트가 최종 심판이라는 대목이 인상적이다. 에이전트가 쓴 코드는 그럴듯하게 틀릴 수 있다. 그 틀을 잡아주는 가장 확실한 기준이 기계로 검증 가능한 테스트라는 것. 구현을 AI에 맡기는 시대의 품질 관리가 어떤 모습일지 하나의 답을 보여준다.

설계 목표에도 시대가 배어 있다. 메모리 사용량은 낮게, 구형 GPU가 달린 기계에서도 버티도록. 의존성 발자국은 작게, 정적 링크 Rust 빌드로. 불필요한 Arc, Mutex, unsafe 사용은 최소화. 그리고 headless-first — 에이전트가 Chromium 인스턴스 하나를 끌고 다니지 않고도 쓸 수 있는 브라우저를 지향한다. 사람보다 자율 에이전트가 웹을 더 많이 오가는 시절이 왔다는 판단이 설계에 그대로 녹아 있다.

## 끝났다고 하기엔 일찍다

작성자 스스로는 완성과 거리가 멀다고 말한다. 여전히 박살나는 사이트가 있고, 남은 WPT 실패 케이스들은 "특별한 종류의 심리전"이라는 표현을 쓴다. 렌더링 문제 하나를 고치면 2008년쯤 누군가 표준화했을 법한, 아무도 모르는 브라우저 동작이 하나 더 튀어나온단다. 브라우저가 왜 수십 년짜리 프로젝트인지 실감 나는 대목이다.

그래도 진짜 웹사이트가 돌고, 진짜 자바스크립트가 실행된다. 쓸 만한 수준에 가까워지고 있다는 것도 부정하기 어렵다.

## 왜 주목할까

브라우저 엔진의 진입장벽은 두 겹이었다. 압도적인 구현 노동량이 하나, 수십 년 쌓인 아키텍처 유산에 대한 지식이 또 하나. 전자를 AI 에이전트가 흡수하고 있고, 후자는 준수 테스트라는 형태로 외부에서 검증할 수 있다는 걸 이 프로젝트가 보여준다. 사람은 방향과 판단을 쥐고, 노동은 기계가 나눠 지는 구조. AI 시대 소프트웨어 개발의 원형 같은 그림이다.

동기도 의미가 깊다. 기존 엔진의 수십 년짜리 짐을 물려받지 않고, 더 적은 메모리로 브라우저를 만들 수 있는가. 그 실험을 해보려 혼자서 시작했다고 한다. 대형 엔진들이 감당해야 하는 역사의 무게 없이 설계할 수 있다면 어떤 브라우저가 나올까. 답은 아직 진행형이다.
