맥미니 서버에서 Claude Code를 쓸 때마다 인증이 풀려서 골치가 아팠다. tmux 하나로 해결한 이야기.

## SSH + AI CLI = 인증 지옥

현재 M2 맥미니와 M4 맥미니, 두 대를 홈 서버로 운용하고 있다. 로컬 LLM이나 각종 AI 에이전트들을 이 기기들에 맡기고, 외출할 때는 M1 맥북에어로 SSH 접속해서 작업하는 방식이다.

처음에는 꽤 만족스러웠다. 맥북에어는 가볍게 들고 다니고, 리소스를 잡아먹는 일은 전부 맥미니들에 맡기면 되었기 때문이다.

그런데 `Claude Code`를 본격적으로 쓰기 시작하면서 아주 번거로운 문제가 하나 발생했다.

## "Not logged in · Please run /login"

이 메시지를 하루에 몇 번이나 봐야 했는지 모르겠다.

SSH로 접속해서 `claude`를 실행하고 작업을 시켜두었는데, 잠시 자리를 비우거나 네트워크가 끊겨서 SSH 세션이 종료되면? 다시 접속했을 때 **인증 절차를 처음부터 다시 밟아야 한다.**

특히 `Claude Code` 같은 툴은 브라우저를 띄워서 인증하는 방식인데, 서버는 모니터도 없는 Headless 환경이다. 매번 인증 링크를 복사해서 로컬 브라우저에 붙여넣고, 승인 버튼 누르고, 다시 터미널로 돌아오는 과정이 한두 번이면 참을 수 있지만 하루에 서너 번씩 반복되니 정말 답답했다.

거기에 한 가지 더 짜증스러운 부분이 있는데, 이 인증 링크가 꽤 길다. 터미널 창 너비를 넘어가면 줄 바꿈이 되는데, 이것을 드래그해서 복사하면 줄 바꿈 부분이 공백으로 들어간다. 그래서 브라우저에 붙여넣으면 URL이 깨져서 인증이 안 되고, 수동으로 공백을 지워야 한다. 이미 번거로운 인증 과정에 이런 사소한 불편까지 겹치니 스트레스가 배가 되었다.

**"아니, 서버는 계속 켜져 있는데 내 접속이 끊겼다고 너까지 로그아웃되면 어떡하니?"**

iOS 개발할 때는 시뮬레이터가 꺼져도 Xcode 세션이 날아가지는 않았는데, 서버 환경은 조금 다르다.

## 원인: SSH 세션이 죽으면 자식 프로세스도 같이 죽는다

혼자서 원인을 찾다가 잘 모르겠어서 Gemini에게 물어보았다. 돌아온 답이 꽤 명쾌했는데, 정리하면 이렇다.

Claude Code는 OAuth 방식으로 인증을 처리한다. 브라우저에서 로그인하면 OAuth 토큰을 받아오고, 이 토큰을 가지고 API와 통신하는 구조다. 문제는 SSH 세션이 끊기면 Claude Code 프로세스 자체가 죽어버린다는 것이다.

SSH로 접속해서 실행한 프로세스들은 해당 세션의 자식 프로세스로 돌아간다. SSH 연결이 끊기면 세션이 종료되고, 세션이 종료되면 그 아래에 매달려 있던 프로세스들도 `SIGHUP` 신호를 받아서 함께 사라진다. Claude Code도 예외가 아니다. 프로세스가 죽으면서 들고 있던 OAuth 인증 상태도 함께 날아가는 것이다.

즉, "인증이 만료되는" 것이 아니라 인증을 들고 있던 프로세스가 통째로 사라지는 것이었다.

그렇다면 답은 하나. **SSH 연결과 무관하게 프로세스가 살아있게 만들면 된다.**

## 해결책: tmux로 세션을 유지하자

그래서 꺼내든 카드가 바로 **`tmux`**이다.

`tmux`는 보통 화면 분할 용도로 많이 알려져 있지만, 서버 환경에서의 진정한 가치는 **'세션 유지(Session Persistence)'**에 있다. tmux가 만들어주는 세션은 SSH 연결과 독립적이다. 접속을 끊어도 tmux 세션 안의 프로세스들은 서버에서 계속 실행된다.

쉽게 말하면 이렇다:

- **tmux 없이**: SSH 접속 → 작업 → SSH 끊김 → 작업 중이던 것을 모두 잃음
- **tmux 있으면**: SSH 접속 → tmux 세션 진입 → 작업 → SSH 끊김 → tmux 세션은 서버에서 계속 유지됨 → 다시 접속해서 붙으면 된다

## 적용 방법

### 1단계: tmux 설치

맥미니 서버에 아직 tmux가 없다면 설치부터.

```bash
brew install tmux
```

### 2단계: 작업용 세션 생성

SSH로 접속한 뒤, 바로 작업을 시작하지 말고 tmux 세션을 먼저 만든다.

```bash
tmux new -s claude
```

`claude`는 세션 이름인데, 본인이 알아볼 수 있는 이름이면 무엇이든 상관없다. `ai-agent`든 `work`든 원하는 대로 정하면 된다.

화면 하단에 초록색 상태바가 뜨면 tmux 환경으로 들어온 것이다. 여기서 Claude Code를 실행하고 최초 인증을 진행한다.

```bash
claude
# (최초 1회 인증 진행)
```

### 3단계: 세션 분리 (Detach)

작업을 걸어두고 자리를 비워야 할 때, 터미널 창을 단순히 닫으면 안 된다. **세션 분리**를 해야 한다.

```
Ctrl + b 를 누르고 → 손을 뗀 뒤 → d
```

`[detached (from session claude)]` 메시지가 뜨면서 원래 쉘로 빠져나온다.

이제 SSH 접속을 끊어도, 맥북에어를 덮어도, 와이파이가 끊겨도 **맥미니 안에서 tmux 세션은 살아 있다.** Claude Code의 인증 상태도 당연히 유지된다.

### 4단계: 다시 붙기 (Attach)

나중에 작업을 재개하고 싶으면 SSH로 접속한 뒤:

```bash
tmux attach -t claude
```

아까 작업하던 화면, 출력 로그, 인증 상태가 그대로 남아 있다.

## 알아두면 좋은 tmux 명령어 몇 가지

실제로 사용해 보면 기본 attach/detach 외에도 몇 가지 알아두면 편리한 것들이 있다.

```bash
# 현재 유지 중인 세션 목록 확인
tmux ls

# 특정 세션 강제 종료 (더 이상 필요 없을 때)
tmux kill-session -t claude

# 세션이 하나뿐일 때 간단하게 붙기
tmux attach
# 또는 줄여서
tmux a
```

tmux 안에서 쓸 수 있는 단축키도 몇 개 알아두면 좋다.

| 단축키 | 동작 |
|--------|------|
| `Ctrl+b` → `d` | 세션 분리 (Detach) |
| `Ctrl+b` → `c` | 새 윈도우 생성 |
| `Ctrl+b` → `n` | 다음 윈도우로 이동 |
| `Ctrl+b` → `p` | 이전 윈도우로 이동 |
| `Ctrl+b` → `%` | 화면 세로 분할 |
| `Ctrl+b` → `"` | 화면 가로 분할 |

필자의 경우 Claude Code 세션을 여러 개 띄워서 각각 다른 프로젝트를 동시에 작업시키고 있다. 윈도우만 전환하면 되므로 꽤 편리하다.

## 실제 워크플로우

이 세팅 이후 필자의 일상적인 작업 흐름은 이렇게 바뀌었다.

1. 카페에서 맥북에어로 SSH 접속 → `tmux a`
2. Claude Code에게 리팩토링 작업 지시
3. `Ctrl+b, d`로 세션 분리하고 커피 한 잔
4. 집에 와서 맥북에어로 SSH 접속 → `tmux a` 해서 결과 확인
5. 필요하면 추가 지시하고 다시 분리

SSH 연결이 끊길까 봐 조마조마하거나, 매번 인증 링크를 복사-붙여넣기할 필요가 없어졌다. 무엇보다 **장시간 걸리는 작업을 걸어두고 편하게 떠날 수 있다**는 점이 가장 크다.

## 꼭 원격이 아니더라도

사실 tmux는 SSH 환경에서만 유용한 것이 아니다. 로컬에서 작업할 때도 쓸 만하다.

예를 들어 기본 터미널에서 Claude Code를 돌리다가, Antigravity 같은 다른 터미널 앱으로 바꾸고 싶을 때가 있다. tmux 없이는 기존 터미널의 세션을 그대로 옮길 수가 없다. 하지만 tmux 위에서 작업하고 있었다면, 어떤 터미널 앱을 열든 `tmux a`만 치면 아까 하던 작업에 바로 붙을 수 있다.

터미널 앱이 갑자기 꺼지거나 실수로 창을 닫아버려도 마찬가지다. tmux 세션은 터미널 앱과 별개로 살아 있으므로, 다시 열어서 붙으면 그만이다. 이런 안정감 때문에 필자는 로컬 작업할 때도 습관적으로 tmux 안에서 시작하는 편이다.

## .zshrc에 함수로 등록해두면 더 편하다

매번 `tmux new -s claude`나 `tmux attach -t claude`를 치는 것도 번거로워서, `.zshrc`에 간단한 함수를 하나 만들어 두었다.

```bash
# ~/.zshrc
cc() {
  tmux attach -t claude 2>/dev/null || tmux new -s claude
}
```

이렇게 해두면 터미널에서 `cc`만 치면 된다. 기존 세션이 있으면 붙고, 없으면 새로 만든다. 세션 이름이나 함수 이름은 취향대로 바꾸면 된다.

## 한 가지 주의사항

tmux 세션도 서버가 재부팅되면 사라진다. 맥미니 서버를 재시작할 일이 있으면 그 전에 중요한 작업을 마무리해 두는 것이 좋다. 아니면 `tmux-resurrect` 같은 플러그인으로 세션 자체를 저장/복원하는 방법도 있다. 사실 거기까지 갈 필요는 아직 느끼지 못했다.

서버 환경에서 AI CLI 도구를 쓴다면 `tmux`는 선택이 아니라 필수다. 5분이면 세팅할 수 있으니 아직 사용하지 않고 있다면 지금 바로 시도해 보기를 권한다.
