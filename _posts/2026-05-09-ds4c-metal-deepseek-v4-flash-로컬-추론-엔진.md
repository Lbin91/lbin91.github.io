## 서론

로컬에서 LLM 돌리는 매력은 참 끝이 없다(이라고 하면서 맥북 팬이 돌아가면 또 당황함).

이전 글 '[DeepSeek V4](/ai/deepseek-v4/)'에서 DeepSeek V4 아키텍처의 혁신을 다룬 적이 있다. 그로부터 얼마 안 돼서 GeekNews에서 또 흥미로운 프로젝트를 발견했다. 이름하여 **ds4.c**. DeepSeek V4 Flash 모델을 Apple Silicon의 Metal GPU에서 직접 굴리기 위해 만들어진 작고 가벼운 네이티브 추론 엔진이다.

범용 GGUF 실행기도 아니고, 다른 런타임을 감싼 얇은 래퍼도 아니다. DeepSeek V4 Flash 하나만을 위해 처음부터 C로 짜내린 코드 베이스다. 단일 모델에 올인하는 그 집념이 인상적이어서 정리해봤다.

## 핵심 내용

### DeepSeek V4 Flash, 왜 빠른가

DeepSeek V4 Flash는 전체 모델 용량은 그대로 유지하면서 **활성 파라미터 수를 대폭 줄인** 변형 모델이다. Mixture-of-Experts(MoE) 구조를 극한까지 밀어붙여서, 추론할 때 실제로 연산에 참여하는 파라미터 비율이 엄청 낮다. Dense 모델과 비교하면 메모리 대역폭 요구량이 확 줄고, 토큰 생성 속도도 비약적으로 올라간다.

이게 로컬 환경에서 특히 강력한 무기가 된다. Apple Silicon은 통합 메모리 아키텍처 덕분에 대용량 모델을 띄울 수 있긴 한데, 메모리 대역폭 자체는 데이터센터 GPU에 비하면 한계가 뚜렷하다. 활성 파라미터가 적은 Flash 변형은 이 병목을 아주 자연스럽게 우회한다. 로컬 추론에 최적화된 설계라는 뜻이다.

### ds4.c의 설계와 구성

ds4.c는 크게 세 가지 핵심 모듈로 나뉜다.

**Metal 그래프 실행기** — Metal Compute Shader를 직접 구성하고 디스패치해서 모델의 각 레이어 연산을 GPU에서 수행한다. 중간에 다른 프레임워크나 추상화 계층을 안 거치니까 오버헤드가 거의 제로에 가깝다. 심지어 코드를 읽어보면 Metal API 호출이 꽤 직관적으로 돼 있다(물론 Metal 자체를 모르면 여전히 알ien 언어다).

**DS4 전용 로딩 및 프롬프트 렌더링** — 모델 가중치를 DeepSeek V4 Flash 고유 포맷에 맞춰 그대로 로드한다. 채팅 템플릿과 프롬프트 포맷도 DS4 사양에 맞춰 렌더링한다. 범용 포맷으로 변환하는 과정이 없으니 로딩이 빠르고, 중간에 정확도가 깎여나가는 일도 없다.

**KV 캐시와 서버 API** — 멀티턴 대화를 위한 KV 상태 관리를 내장하고, 간단한 HTTP 서버 API도 제공한다. 로컬에서 OpenAI 호환 엔드포인트처럼 쓸 수 있어서 기존 도구 체인이랑 연동하는 것도 수월하다. 이 정도면 진짜 쓸 만한 도구다.

### 범용 런타임과의 차이

llama.cpp나 Ollama 같은 범용 GGUF 실행기는 여러 모델 아키텍처를 다 지원해야 하니까 필연적으로 추상화 계층이 있다. 반면 ds4.c는 DeepSeek V4 Flash 하나만 바라보고 설계됐다. 불필요한 분기 로직, 범용 텐서 뷰어, 포맷 변환기 같은 게 전부 빠져 있다.

결과적으로 코드베이스가 엄청 작고 읽기 쉽다. 프로젝트 전체가 한눈에 들어올 정도로 심플한데, 해당 모델에 한해서는 범용 엔진보다 더 효율적인 실행 경로를 제공한다. 적은 걸로 더 많이 하는 거, 개발자라면 이 매력을 모를 수 없다.

## 왜 주목할까

**첫째, Apple Silicon 로컬 LLM의 새로운 가능성이다.** M 시리즈 칩의 Metal GPU를 직접 활용하는 네이티브 엔진이 등장했다는 것 자체가 의미 있다. 클라우드 API 없이도 꽤 강력한 추론 성능을 로컬에서 끌어낼 수 있는 길이 점점 넓어지고 있다.

**둘째, 소프트웨어 공학적으로도 배울 게 많다.** 범용성을 버리고 특정 모델에 대한 최적화를 선택한 결단, Metal API를 직접 다루는 방식, 최소한의 추상화로 성능을 끌어내는 설계 — 다 훌륭한 레퍼런스다. 이런 코드 읽는 재미가 따로 있다.

**셋째, 오픈소스 로컬 AI 생태계의 다양성 측면에서도 환영할 일이다.** llama.cpp 하나에 의존하던 생태계에 새로운 선택지가 생겼다. 경쟁은 결국 사용자에게 더 나은 성능과 경험을 가져다준다(자본주의가 무조건 나쁜 건 아닌 셈).

## 정리

ds4.c는 DeepSeek V4 Flash 모델을 Apple Silicon에서 최고 효율로 실행하기 위해 태어난 네이티브 추론 엔진이다. 범용성 대신 특화성을 선택했고, 그 대가로 작은 코드베이스와 낮은 오버헤드를 얻었다. Metal 그래프 실행기, DS4 전용 로딩, KV 캐시, 서버 API까지 다 갖추고 있어 실용적인 도구로도 충분하다.

로컬에서 대형 언어 모델 가지고 놀어본 적 있다면 ds4.c는 꼭 한번 살펴볼 만하다. Apple Silicon 기반 로컬 추론 생태계가 앞으로 또 어떻게 발전할지 기대된다. 맥북 팬이 더 자주 돌아가겠지만, 그건 어차피 감수해야 할 몫이다.
