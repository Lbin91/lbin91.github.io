맥미니 서버에서 Claude Code를 쓸 때마다 인증이 풀려서 미치는 줄 알았다. tmux 하나로 해결한 이야기.

## SSH + AI CLI = 인증 지옥

최근 M2 맥미니를 홈 서버로 들이면서 로컬 LLM이나 각종 AI 에이전트들을 이 녀석에게 맡기고 있다. 메인 작업은 M4 맥북이나 다른 PC에서 하고, 무거운 작업이나 장시간 돌아가야 하는 봇들은 맥미니 서버에 SSH로 붙어서 시키는 식이다.

처음엔 꽤 만족스러웠다. 맥북은 가볍게 쓰고, 리소스 잡아먹는 일은 전부 서버에 던지면 되니까.

그런데 `Claude Code`를 본격적으로 쓰기 시작하면서 아주 귀찮은 문제가 하나 발생했다.

## "로그인이 만료되었습니다. 다시 인증해주세요."

이 메시지를 하루에 몇 번을 본 건지 모르겠다.

SSH로 접속해서 신나게 `claude`를 실행하고 작업을 시켜뒀는데, 잠시 자리를 비우거나 네트워크가 끊겨서 SSH 세션이 종료되면? 다시 접속했을 때 **인증 절차를 처음부터 다시 밟아야 한다.**

특히 `Claude Code` 같은 툴은 브라우저를 띄워서 인증하는 방식인데, 서버는 모니터도 없는 Headless 환경이다. 매번 인증 링크를 복사해서 로컬 브라우저에 붙여넣고, 승인 버튼 누르고, 다시 터미널로 돌아오고... 이게 한두 번이면 참겠는데 하루에 서너 번씩 반복되니까 진짜 화가 났다.

**"아니, 서버는 계속 켜져 있는데 내 접속이 끊겼다고 너까지 로그아웃되면 어떡하니?"**

iOS 개발할 때는 시뮬레이터가 꺼져도 Xcode 세션이 날아가진 않았는데, 서버 세계는 좀 다르더라.

## 원인: SSH 세션이 죽으면 자식 프로세스도 같이 죽는다

곰곰이 생각해보니 문제의 본질은 단순했다.

SSH로 접속해서 실행한 프로세스들은 해당 세션의 **자식 프로세스**로 돌아간다. SSH 연결이 끊기면 세션이 종료되고, 세션이 종료되면 그 아래에 매달려 있던 프로세스들도 `SIGHUP` 신호를 받아서 같이 사라진다.

즉, **Claude Code의 인증 상태가 날아가는 게 아니라, Claude Code 프로세스 자체가 죽어버리는 거다.**

그렇다면 답은 하나. **SSH 연결과 무관하게 프로세스가 살아있게 만들면 된다.**

## 해결책: tmux로 세션을 살려두자

그래서 꺼내든 카드가 바로 **`tmux`**다.

`tmux`는 보통 화면 분할 용도로 많이 알려져 있지만, 서버 환경에서의 진정한 가치는 **'세션 유지(Session Persistence)'**에 있다. tmux가 만들어주는 세션은 SSH 연결과 독립적이다. 내가 접속을 끊어도 tmux 세션 안의 프로세스들은 서버에서 계속 돌아간다.

쉽게 말하면 이렇다:

- **tmux 없이**: SSH 접속 → 작업 → SSH 끊김 → 작업 중이던 거 다 날아감
- **tmux 있으면**: SSH 접속 → tmux 세션 진입 → 작업 → SSH 끊김 → tmux 세션은 서버에서 계속 살아있음 → 다시 접속해서 붙으면 됨

## 적용 방법

방법은 허무할 정도로 간단하다.

### 1단계: tmux 설치

맥미니 서버에 아직 tmux가 없다면 설치부터.

```bash
brew install tmux
```

### 2단계: 작업용 세션 생성

SSH로 접속한 뒤, 바로 작업을 시작하지 말고 tmux 세션을 먼저 만든다.

```bash
tmux new -s claude
```

`claude`는 세션 이름인데, 본인이 알아볼 수 있는 이름이면 아무거나 상관없다. `ai-agent`든 `work`든 편한 대로 짓자.

화면 하단에 초록색 상태바가 뜨면 tmux 환경으로 들어온 것이다. 여기서 Claude Code를 실행하고 최초 인증을 진행한다.

```bash
claude
# (최초 1회 인증 진행)
```

### 3단계: 세션 분리 (Detach)

작업을 걸어두고 자리를 비워야 할 때, 터미널 창을 그냥 닫으면 안 된다. **세션 분리**를 해야 한다.

```
Ctrl + b 를 누르고 → 손을 뗀 뒤 → d
```

`[detached (from session claude)]` 메시지가 뜨면서 원래 쉘로 빠져나온다.

이제 SSH 접속을 끊어도, 맥북을 덮어도, 와이파이가 끊겨도 **맥미니 안에서 tmux 세션은 살아있다.** Claude Code의 인증 상태도 당연히 유지된다.

### 4단계: 다시 붙기 (Attach)

나중에 작업을 재개하고 싶으면 SSH로 접속한 뒤:

```bash
tmux attach -t claude
```

아까 작업하던 화면, 출력 로그, 인증 상태가 그대로 남아있다.

## 알아두면 좋은 tmux 명령어 몇 가지

실제로 써보면 기본 attach/detach 외에도 몇 가지 알아두면 편한 것들이 있다.

```bash
# 현재 살아있는 세션 목록 확인
tmux ls

# 특정 세션 강제 종료 (더 이상 필요 없을 때)
tmux kill-session -t claude

# 세션이 하나뿐일 때 간단하게 붙기
tmux attach
# 또는 줄여서
tmux a
```

tmux 안에서 쓸 수 있는 단축키도 몇 개 알아두면 좋다.

| 단축키 | 동작 |
|--------|------|
| `Ctrl+b` → `d` | 세션 분리 (Detach) |
| `Ctrl+b` → `c` | 새 윈도우 생성 |
| `Ctrl+b` → `n` | 다음 윈도우로 이동 |
| `Ctrl+b` → `p` | 이전 윈도우로 이동 |
| `Ctrl+b` → `%` | 화면 세로 분할 |
| `Ctrl+b` → `"` | 화면 가로 분할 |

나 같은 경우는 Claude Code 세션 하나, LLM 서버 로그 보는 세션 하나 이런 식으로 윈도우를 나눠서 쓰고 있다.

## 실제 워크플로우

이 세팅 이후 내 일상적인 작업 흐름은 이렇게 바뀌었다.

1. 카페에서 아이패드로 SSH 접속 → `tmux a`
2. Claude Code에게 리팩토링 작업 지시
3. `Ctrl+b, d`로 세션 분리하고 커피 한 잔
4. 집에 와서 맥북으로 SSH 접속 → `tmux a` 해서 결과 확인
5. 필요하면 추가 지시하고 다시 분리

SSH 연결이 끊길까 봐 조마조마하거나, 매번 인증 링크를 복붙할 필요가 없어졌다. 무엇보다 **장시간 걸리는 작업을 걸어두고 편하게 떠날 수 있다**는 게 가장 크다.

## 한 가지 주의사항

tmux 세션도 서버가 재부팅되면 사라진다. 맥미니 서버를 재시작할 일이 있으면 그 전에 중요한 작업을 마무리해두자. 아니면 `tmux-resurrect` 같은 플러그인으로 세션 자체를 저장/복원하는 방법도 있긴 한데, 솔직히 거기까지 갈 필요는 아직 못 느꼈다.

서버 환경에서 AI CLI 도구를 쓴다면 `tmux`는 선택이 아니라 필수다. 딱 5분이면 세팅할 수 있으니 안 쓰고 있다면 지금 바로 해보시길.
