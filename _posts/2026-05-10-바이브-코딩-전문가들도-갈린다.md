컴퓨터공학 교수가 "바이브 코딩은 가짜다"라고 깠다가, 레딧의 15년 차 시니어 개발자들에게 역관광을 당했다(팝콘각이다).

오늘 r/claudecode를 뜨겁게 달군 두 개의 사건이 있다. 하나는 남의 API 키로 공짜 코딩한다는 밈이고, 다른 하나는 학계 교수가 바이브 코딩을 깠다가 현업 개발자들의 맹폭을 맞은 사태다. 둘 다 "바이브 코딩"이라는 키워드로 묶이지만 온도는 완전히 달랐다.

## "바이브 코더들의 무료 급식소" 밈

추천 680개를 찍은 밈 게시글의 요지는 심플하다. 바이브 코더들이 남의 OpenAI API 키를 슬쩍 가져다 공짜로 코딩한다는 웃픈 풍자다.

가장 많은 공감을 얻은 댓글이 압권이었다. "진짜 바이브 코더는 git local만 쓴다. 애초에 git push를 할 줄 몰라서 키 유출도 안 된다"는 뼈 때리는 농담이었다. 웃어넘기기엔 AI 코딩 시대의 처참한 보안 불감증을 정확히 찔렀다.

## 컴퓨터 과학자 vs 실무 엔지니어의 정면충돌

더 흥미진진했던 건 컴퓨터공학 박사의 비판 글에서 시작된 설전이었다. "CS 기초 지식 없이 LLM에만 의존하는 바이브 코딩은 기술적 파멸을 부른다"는 원론적인 일침이었다.

하지만 현업 개발자들의 반격은 매서웠다. 15년 차 시니어 엔지니어부터 심지어 다른 컴퓨터공학 교수까지 등판해 반박을 쏟아냈다.

> "충분히 정밀하게 지시할 수만 있다면, 첫 번째 시도에 99% 정상 작동하는 코드를 뽑아낼 수 있다."

학계와 현업의 베테랑들조차 LLM 코딩의 파괴력을 인정하고 있다는 생생한 증거다.

## 양측의 논리가 모두 팽팽하다

**바이브 코딩 옹호론:**
"어셈블리 시절엔 C 언어 쓰는 놈들을 가짜 프로그래머라 불렀고, C 시절엔 파이썬 쓰는 사람을 무시했다. 도구를 다루는 인터페이스가 자연어로 진화했을 뿐이다. 정밀하게 의도를 설계하고 지시하는 것 자체가 21세기 프로그래밍의 새로운 본질이다."

**전통적 기본기 옹호론:**
"코드가 돌아가는 원리를 모르면 에러 로그가 터졌을 때 디버깅을 아예 못 한다. 규모가 커지고 아키텍처가 꼬였을 때 기본기 없는 바이브 코더는 절벽 아래로 떨어진다."

둘 다 너무 맞는 말이라 반박하기가 어렵다(골 때린다).

## 정리

바이브 코딩 논쟁은 단순한 세대 갈등이나 실력 다툼이 아니다. 소프트웨어 엔지니어링이라는 행위의 정의 자체가 다시 쓰이고 있는 과도기의 진통이다.

개인적으로는 이렇게 결론 내리고 싶다. 바이브 코딩이든 정통 코딩이든, 프로덕션에서 버그 없이 안정적으로 도는 결과물을 내놓는 자가 승자다.

다만 내가 만든 코드가 왜 도는지조차 모른다면 언젠가 반드시 대가를 치르게 된다. 그 기본기만 챙겨가면서 AI의 속도를 흡수하는 사람, 그 사람이 진짜 무서운 엔지니어다. (그리고 API 키는 제발 내 돈 내고 쓰자. 진짜로.)
