Multi-Token Prediction(MTP) 지원이 일주일 만에 급속도로 확산했다. 로컬 LLM 인프라의 주요 변화를 정리한다.

## Qwen 3.6 27B MTP, Unsloth에서 2.5배 속도 향상

Unsloth UD XL 양자화를 적용한 Qwen 3.6 27B에 MTP를 그래프트(graft)한 결과 2.5배 처리량 향상을 달성했다(120업보트, 50개 댓글). 아직 머지되지 않은 llama.cpp PR을 사용한 것으로, 실운영 적용에는 시간이 필요하지만 결과 자체는 인상적이다.

V100 32GB에서도 Qwen 3.6 27B MTP가 54 TPS로 구동됐다는 보고도 있었다(68↑, 34💬). 같은 환경에서 35B MoE는 105-110 TPS로, MoE가 여전히 속도 우위지만 27B 밀집 모델의 실용성이 크게 개선됐다.

## Strix Halo에서 MTP 구동

AMD Strix Halo AI Max 395(128GB DDR5 8000)에서 llama.cpp MTP PR을 테스트한 결과가 공유됐다(92↑, 30💬). AMD ROCm 환경에서도 MTP가 정상 작동한다는 확인으로, Intel/NVIDIA에 이어 AMD까지 MTP 생태계가 열렸다.

## Gemma 4, 어디에 쓰나

"Gemma 4를 무엇에 사용하나요?"라는 질문에 118개 댓글이 달렸다(92↑). 필기 분석과 비전 작업에서 Qwen보다 우수하다는 평가가 많았다. 채팅 품질에서도 Gemma를 선호한다는 반응이 있었다. 반면 코딩에서는 여전히 Qwen이 앞선다는 의견이 지배적이었다.

## Ollama, 인증 없는 메모리 유출 취약점

Ollama에 치명적인 비인증 메모리 유출 취약점이 발견됐다(85↑, 35💬). "Ollama를 안 쓰는 또 하나의 이유"라는 댓글이 대표적이다. 로컬 추론 도구의 보안 기본기가 다시 도마에 올랐다. Ollama는 설치 편의성으로 널리 쓰이지만, 보안 감사가 충분치 않다는 지적이 계속돼왔다.

## GPT-5.5 xhigh, 코딩 에이전트 최강… 하위 등급은 약해

GPT-5.5를 40개 실제 엔지니어링 과제에서 테스트한 결과, xhigh 등급은 측정된 코딩 에이전트 중 최강이었지만 하위 추론 등급은 예상보다 현저히 약했다(38↑, 20💬). "다른 벤치마크와 결과가 다른데 왜 그런가"라는 질문에 대한 답은 아직 없다.

## DeepSeek TUI, GitHub #1 트렌딩

DeepSeek가 오픈소스 TUI 코딩 에이전트를 공개해 GitHub 트렌딩 1위에 올랐다(33↑, 5💬). 그러나 "이미 opencode, Claude Code 같은 도구가 있는데 차별점이 무엇이냐"는 반응도 있었다.

## 시사점

MTP가 단순한 실험실 기술에서 실제 로컬 배포 환경으로 빠르게 확산하고 있다. V100, Strix Halo 등 다양한 하드웨어에서 검증이 이뤄지는 점이 의미 있다. 반면 Ollama 취약점은 로컬 LLM 도구의 보안 기본기에 대한 경고다.
