r/claudecode에서 score 303을 받은 게시물이 있었다. 제목은 단순히 "Anthropic이란 이런 것". 내용은 "현실 vs Anthropic의 주장"을 나란히 놓고 비교하는 밈 이미지였다. 코멘트는 대부분 공감.

Opus 4.7이 발표될 때 Anthropic은 장기 실행 작업 처리 향상, 3배 고해상도 비전, 자가 검증 기능 강화를 내세웠다. 그런데 실제 써보는 유저들의 반응은 전혀 달랐다. 파일을 먼저 읽으라 해도 무시하고 반복 수정하는 문제, 작업을 잊어버리고 확인 없이 다음으로 넘어가는 문제가 속출했다. "추측하지 말라고 명시했는데도 계속 추측을 한다. 더 이상 AI가 아니라 점쟁이다"라는 댓글이 많은 공감을 받았다.

물론 옹호하는 목소리도 있었다. "마지막 2%의 오류를 잡는 게 앞의 98%보다 훨씬 어렵지만, 에이전트 작업에서 그 개선은 매우 중요하다"는 의견도 있었다. 하지만 전반적인 분위기는 기대치에 못 미친다는 쪽이었다.

## 모델 탓인가, 하네스 탓인가

여기서 재밌는 논쟁이 하나 등장한다. 이게 Opus 4.7 모델 자체의 문제인지, 아니면 Claude Code라는 하네스의 문제인지를 두고 의견이 갈렸다.

이 질문에 간접적으로 답을 주는 실험 결과가 올라왔다. Opus 4.7, DeepSeek V4 Flash, 로컬 Qwen3.6 27B를 모두 같은 Claude Code 하네스에서 돌려봤는데, 모델 간 성능 격차가 예상보다 훨씬 작았다는 거다. 비싼 최신 모델이든 가성비 오픈소스 모델이든, 같은 환경에서 돌리면 결과가 비슷하다.

이건 꽤 큰 시사점이다. 지금까지는 "어떤 모델을 쓰느냐"가 생산성의 핵심이라고 믿었는데, 실제로는 "어떤 도구 환경에서 모델을 구동하느냐"가 더 큰 비중을 차지할 수 있다는 뜻이다.

## 새로운 경쟁자: jcode

이 흐름과 맞물려 새로운 오픈소스 에이전트 하네스인 jcode가 등장했다. Claude Code보다 20배 메모리 효율이 좋고, Codex CLI보다 63배 빠른 코드 생성을 지원하며, 병렬 세션과 스웜 확장까지 가능하다고 밝혔다. 차기 지배적 오픈소스 하네스를 노린다는 야심 찬 선언이었다.

다만 주의할 점이 있다. 서드파티 도구에서 Claude OAuth를 그대로 사용하면 계정이 정지될 수 있다는 경고가 최다 추천 댓글로 올라왔다. jcode가 아무리 좋아도, 인증 방식에서 문제가 생기면 소용이 없다. API 키 직접 사용이나 자체 인증 방식을 써야 안전하다.

## 로컬 모델의 약진

"최신이 항상 최고는 아니다"는 교훈도 곳곳에서 등장하고 있다. r/localllm에서는 Qwen3.6 27B가 로컬 코딩 에이전트로 실전 사용 가능한 수준이라는 평가가 확산 중이다. AMD Strix Halo 128GB에서 122B 모델을 25토큰/초로 구동하는 성과도 공유됐다. 하드웨어와 모델 양쪽의 진전이 체감되는 수준이다.

r/openclaw에서도 비슷한 맥락의 불만이 나왔다. v4.24 업데이트로 게이트웨이가 대규모 장애를 겪으면서 "고치는 시간보다 쓰는 시간이 더 많다"는 반응이 커뮤니티에 퍼졌다. 클라우드 서비스에 의존할 때 발생하는 리스크가 체감된 사례다.

## 왜 주목해야 하나

지금 AI 에이전트 생태계에서 가장 중요한 변화는 모델 경쟁이 아니라 **환경 경쟁**으로 무게중심이 이동하고 있다는 거다. Claude Code, jcode, Codex CLI — 어떤 하네스에서 모델을 구동하느냐가 생산성을 가른다.

물론 모델 자체의 능력도 중요하다. 하지만 하네스가 제공하는 컨텍스트 관리, 파일 시스템 접근, 병렬 처리 능력이 모델 간 격차를 좁히거나 뒤집을 수 있다는 걸 이번 실험이 보여줬다.

r/zaiglm에서는 GLM-5.1 Pro 플랜으로 30일간 10억 토큰을 소비한 사용기도 올라왔다. Claude Code Desktop에 Z.ai 코딩 플랜을 연동하는 튜토리얼까지 공유되고 있다. 다양한 모델을 같은 하네스에서 오가며 쓰는 게 점점 보편화되는 추세다.

## 정리

밈이 말해주듯 Anthropic의 주장과 현실 사이에는 간극이 있다. 하지만 그 간극의 원인이 반드시 모델 탓만은 아닐 수 있다. 에이전트 하네스의 설계가 생산성에 미치는 영향이 모델 선택만큼, 어쩌면 그 이상 중요해지고 있다.

앞으로는 "어떤 모델을 쓸까"보다 "어떤 환경에서 어떻게 모델을 활용할까"가 핵심 질문이 될 거다. 그리고 그 답은 반드시 클라우드 최신 모델이 아닐 수 있다.
