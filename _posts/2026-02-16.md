설치는 쉬울 줄 알았는데, config 파일 하나 때문에 한참을 헤맸다. 그리고 PM2로 띄우는 순간의 짜릿함.

## 오랜만의 venv, 그리고 낯선 에러

1편에서 `pip install -r requirements.txt`까지는 끝냈다. 의존성 패키지 몇 개가 deprecated 경고를 뱉긴 했지만, 일단 설치는 됐으니 넘어가자 싶었다.

이제 핵심인 설정 파일 `config.yaml`을 건드릴 차례.

Zhipu AI(GLM)에서 발급받은 API Key와 텔레그램 봇 토큰을 각각의 자리에 꼼꼼히 붙여넣었다. README 예시를 따라서 했으니 문제없을 거라 생각했다.

```bash
python main.py
```

터미널에 로그가 주르륵 올라오면서 봇이 시작됐다. "오, 된다?" 싶어서 텔레그램을 열고 봇한테 "안녕"을 보냈다.

그런데 돌아온 건 답변이 아니라 터미널의 빨간 에러 메시지였다.

```
Error: Anthropic API Key missing
```

## 범인은 'Default Provider'

"뭐? Anthropic? 나 GLM 쓴다고 했잖아."

처음엔 코드 버그인 줄 알았다. 분명 `config.yaml`에 GLM API 키를 넣었는데, 왜 Anthropic 키를 찾는 걸까?

로그를 한 줄씩 읽어보니 문제가 보였다.

```yaml
# config.yaml (문제의 부분)
agents:
  defaults:
    workspace: "~/.nanobot/workspace"
    model: "anthropic/claude-opus-4.5"  # <-- 여기가 문제
```

아래쪽에 아무리 GLM 관련 설정을 넣어도, 정작 메인 `defaults` 섹션의 `model` 값이 Anthropic으로 박혀있었던 거다. 이 필드가 글로벌 기본값 역할을 하는데, README 예시를 그대로 복붙하는 바람에 이걸 안 바꿨다.

```yaml
# 수정 후
agents:
  defaults:
    workspace: "~/.nanobot/workspace"
    model: "zhipu/glm-4"  # GLM-4.7로 변경
```

이렇게 바꾸고 다시 실행하니 드디어 GLM API를 호출하기 시작했다.

## GLM-4 vs 5 (feat. 그래도 4가 안정적)

모델은 GLM-4로 설정했다. 어제 밤부터 Zhipu AI의 Coding Plan Pro 요금제에서도 GLM-5가 풀렸다는 소식에 바로 설정을 바꿔봤다. 그런데 막상 nanobot에 `zhipu/glm-5.0`으로 등록하니 응답이 제대로 오지 않았다. API 호출은 되는데 답변이 이상하거나, 중간에 끊기는 현상이 자주 발생했다. 혹시 nanobot과 GLM-5 간의 호환성 이슈인가 싶어서 다시 GLM-4.7로 내렸다. 최신 모델이 항상 좋은 건 아니라는 교훈을 얻었다.

설정을 마치고 다시 텔레그램으로 메시지를 보냈다.

> **나:** "지금 시간 알려줘"
> **Nanobot:** "현재 시각은 오후 3시 42분입니다."

드디어 성공. 봇이 정상적으로 답변을 내뱉는다.

텔레그램으로 몇 가지 명령어를 더 던져봤다. 간단한 계산, 날씨 조회(API 연동 필요), 파일 목록 조회 같은 것들. 대부분 잘 작동했는데, 파일 목록 조회에서 살짝 걸렸다. workspace 디렉토리 밖은 접근이 안 되더라. "아, 권한 제어가 실제로 작동하고 있구나" 싶어서 오히려 안심이 됐다.

## PM2로 '죽지 않는 봇' 만들기

테스트는 성공했으니, 이제 터미널을 꺼도 봇이 죽지 않도록 PM2에 태울 차례다.

예전에 PM2 글을 쓸 때 배웠던 게 여기서 빛을 발한다. Python 가상환경 경로만 제대로 잡아주면 된다.

```bash
pm2 start main.py --name "nanobot" \
  --interpreter ./venv/bin/python \
  -- --gateway-port 8000
```

`--interpreter` 옵션으로 venv 안의 파이썬을 지정하고, `--` 뒤에는 `main.py`에 넘길 인자(gateway 포트)를 붙였다.

```bash
pm2 save
pm2 startup
```

`pm2 list`를 쳐보니 `nanobot` 프로세스가 `online` 상태로 예쁘게 떠 있다. 맥미니가 업데이트 때문에 재부팅되어도 이제 자동으로 다시 올라온다.

터미널을 닫고, SSH 연결을 끊고, 맥북에어를 덮었다. 그리고 몇 시간 뒤 다시 텔레그램으로 봇한테 말을 걸어봤다.

> **나:** "아직 살아있어?"
> **Nanobot:** "네, 계속 대기 중입니다."

완벽하다.

## 앞으로의 계획: 보안 검증

일단 설치와 구동은 성공했다. OpenClaw를 메인 서버에 들이지 못했던 이유가 보안이었던 만큼, Nanobot도 바로 실무에 투입하진 않을 생각이다.

당분간은 이것저것 찔러보면서 자체 검증을 해볼 예정이다.

1. **파일 시스템 접근 범위**: workspace 밖으로 나갈 수 있는지, 시스템 파일(/etc, /var 등)은 읽을 수 있는지 테스트
2. **명령어 실행 권한**: `rm -rf`나 `sudo` 같은 위험한 명령어가 실제로 막히는지 확인
3. **외부 접근 제어**: 텔레그램 봇이니까 기본적으로 외부에서 들어오는 건데, 허가된 사용자만 쓸 수 있는지 체크

충분히 안전하다는 확신이 들면, 그때 비로소 내 소중한 프로젝트 코드들을 맡겨볼 생각이다. 코드 리뷰 자동화, 로그 분석, 정기 백업 스크립트 관리 같은 것들. 1편에서 꿈꿨던 일들을 하나씩 시켜보려고 한다.

일단 지금은 "말 잘 듣는 비서 한 명 구했다" 정도의 단계다. 본격적인 업무 투입은 검증이 끝난 다음이다.
