## 서론: 에이전트가 에이전트를 부른다

2026년 6월, AI 에이전트 생태계는 "하나의 에이전트가 모든 걸 다 한다"는 모델에서 벗어나 **에이전트 간 협업**이라는 새로운 패러다임으로 이동하고 있다. 하나의 에이전트가 코딩도 하고, 검색도 하고, 배포도 하는 시대는 저물고 있다. 대신, 각자 잘하는 일에 특화된 에이전트들이 서로 작업을 위임하고 결과를 조합하는 구조가 떠오르고 있다.

이 맥락에서 r/openclaw 커뮤니티에 흥미로운 프로젝트가 올라왔다. 사용자 u/9900_BEAST_0099가 **OpenClaw용 A2A(Agent-to-Agent) 플러그인**을 오픈소스로 공개한 것이다. 핵심 질문은 단순하면서도 강력하다 — "에이전트가 다른 에이전트에게 일을 맡기는 것을, OpenClaw의 기본 기능처럼 자연스럽게 만들 수 없을까?"

이 플러그인이 무엇을 하는지, 왜 주목해야 하는지, 그리고 에이전트 생태계에 어떤 시사점을 던지는지 정리해본다.

## 핵심 내용

### 1. `remote_agent` — 위임을 하나의 도구로 압축하다

A2A 플러그인이 추가하는 가장 중요한 것은 `remote_agent`라는 단일 도구다. OpenClaw 에이전트가 이 도구를 호출하면, 원격에 있는 다른 에이전트에게 작업을 요청할 수 있다.

이 구조의 핵심은 **"접착제(glue) 코드"를 없애는 것**이다. 기존에 에이전트 간 통신을 구현하려면 API 엔드포인트를 설정하고, 요청/응답 포맷을 맞추고, 에러 처리를 하고, 상태를 추적하는 — 그 모든 것을 직접 짜야 했다. A2A 플러그인은 이를 하나의 도구 호출로 추상화한다.

```text
# 개념적 흐름
OpenClaw 에이전트
    │
    ├── remote_agent("코드 리뷰 에이전트", task="이 PR 검토해줘")
    │       │
    │       └── 원격 에이전트가 작업 수행
    │               │
    │               └── 결과 + continuation state 반환
    │
    ├── 결과를 받아서 다음 단계 진행
    │
    └── 나중에 continuation state로 후속 작업 재개 가능
```

개발자가 강조한 부분은 이것이다: 위임이 "임시방편의 접착제 더미"가 아니라 **OpenClaw의 기본 요소(primitive)**처럼 느껴져야 한다는 것. 즉, 에이전트가 `remote_agent`를 부르는 것이 `web_search`나 `read`를 부르는 것만큼이나 자연스러워야 한다는 철학이다.

### 2. Continuation State — "나중에 이어서"가 가능해진다

여기서 진짜 흥미로운 부분이 나온다. **작업 상태의 지속성(durability)**이다.

일반적인 에이전트 간 통신은 요청-응답으로 끝난다. A가 B에게 작업을 맡기면, B가 결과를 돌려주고 끝. 하지만 복잡한 작업은 한 번에 끝나지 않는다. "이 부분은 지금 답을 못 주겠는데, 데이터를 더 모아서 내일 다시 얘기하자" 같은 상황이 에이전트 세계에서도 발생한다.

A2A 플러그인은 원격 에이전트가 **continuation state**(작업 연속 상태)를 반환하면, OpenClaw가 이를 그대로 보존한다. 그리고 나중에 이 상태를 그대로 재생(replay)해서 후속 작업을 이어갈 수 있다.

```text
# Continuation 시나리오
1. OpenClaw → 원격 에이전트: "이 데이터셋 분석해줘"
2. 원격 에이전트 → OpenClaw: "1차 분석 완료 + continuation={상태 정보}"
3. (시간 경과)
4. OpenClaw → 원격 에이전트: "이전 분석에 이어서 추가 질문이 있어"
   (continuation state를 그대로 전달 → 맥락이 보존됨)
```

이것이 왜 중요한가? 기존 방식이라면 후속 작업을 할 때 **처음부터 맥락을 다시 설명**해야 한다. 토큰 낭비, 시간 낭비, 그리고 맥락 누락으로 인한 품질 저하가 발생한다. Continuation state는 이 모든 것을 해결한다.

### 3. 로컬 데모로 5분 만에 전체 루프 증명하기

오픈소스 프로젝트가 자주 겪는 문제가 있다 — "좋은데, 어떻게 쓰는 건지 감이 안 잡혀." 이 플러그인은 `openclaw a2a demo run`이라는 명령 하나로 이 문제를 해결한다.

데모가 하는 일:
1. **결정론적 로컬 A2A 피어를 시작** — 외부 서버 없이 로컬에서 돌아가는 테스트용 에이전트
2. **작업 요청 전송** — `remote_agent` 도구를 통해 작업을 보냄
3. **작업 감시** — 진행 상황을 추적
4. **Continuation 출력** — `summary.continuation`을 출력해서 상태 보존 확인
5. **후속 작업 재생** — 보존된 continuation으로 하나의 후속 작업 실행

개발자가 의도적으로 **아웃바운드 전용(outbound-first)**으로 설계한 것도 눈여겨볼 만하다. 인바운드 지원(외부에서 내 에이전트로 작업을 보내는 기능)도 있지만, "공용 네트워킹에 들어가기 전에 계약(contract)을 확인할 수 있도록" 첫 번째 성공 경로는 아웃바운드만 남겨뒀다. 보안을 고려한 설계다.

## 왜 주목할 만한가

### 에이전트 생태계의 "API 혁명"이 오고 있다

소프트웨어 세계를 생각해보자. 초기에는 모놀리thic 애플리케이션이 전부였다. 그러다 마이크로서비스가 등장하고, 각 서비스가 API로 통신하는 구조가 표준이 되었다. 에이전트 세계도 같은 궤적을 걷고 있다.

지금은 하나의 에이전트가 모든 걸 처리하는 시대다. 하지만 곧 각 에이전트가 자신의 전문 영역을 가지고, 서로 작업을 위임하고, 결과를 조합하는 시대가 올 것이다. 코드 리뷰 에이전트, 테스트 작성 에이전트, 문서화 에이전트가 하나의 워크플로우에서 협업하는 구조다.

A2A 플러그인은 이 변화의 **초기 신호**다. 위임이 "직접 짜는 것"에서 "도구 하나로 부르는 것"으로 바뀌는 순간을 보여준다.

### 상태 보존이 에이전트 협업의 열쇠

가장 혁신적인 부분은 continuation state다. 인간도 그렇다 — 동료에게 "그때 하던 거 이어서 해줘"라고 말할 수 있는 건, 그 동료가 이전 작업의 맥락을 기억하고 있기 때문이다. 에이전트도 마찬가지다.

현재 대부분의 에이전트 협업 접근법은 **상태 비저장(stateless)**이다. 매번 새로운 요청에 전체 맥락을 실어 보낸다. 이건 마치 매번 새로 입사한 동료에게 처음부터 상황을 설명하는 것과 같다. A2A 플러그인의 continuation 접근법은 이 문제에 대한 깔끔한 해법을 제시한다.

### 오픈소스 커뮤니티의 속도

이 플러그인이 한 회사의 제품팀이 아니라 **개인 개발자**에 의해 만들어졌다는 점도 주목할 만하다. OpenClaw 같은 에이전트 플랫폼이 제공하는 확장성이 이미 충분히 성숙해져서, 개인이 에이전트 간 협업이라는 복잡한 문제를 플러그인으로 풀 수 있는 단계에 왔다는 뜻이다.

커뮤니티 반응도 긍정적이다. 실사용 사례 문서화 요청이 이어지고 있으며, "5분 안에 첫 성공 경로를 증명할 수 있는가?"라는 개발자의 질문에 사용자들이 직접 피드백을 주고 있는 구조다. 오픈소스 프로젝트가 성장하는 건강한 패턴이다.

## 정리: 위임은 곧 확장성이다

A2A 플러그인이 제안하는 것은 단순한 기능 추가가 아니다. **에이전트의 확장 모델**에 대한 하나의 답이다.

하나의 에이전트가 할 수 있는 일에는 한계가 있다. 컨텍스트 윈도우도, 도구의 수도, 처리 속도도. 하지만 에이전트가 다른 에이전트에게 작업을 위임할 수 있다면, 이 한계를 수평적으로 넓힐 수 있다. 전문화된 에이전트들을 조합해서 복잡한 작업을 수행하는 — 마치 인간 조직이 부서별로 나뉘어 협업하는 것처럼.

물론 아직 해결해야 할 문제가 많다. 에이전트 간 신뢰, 보안, 비용 추적, 실패 처리 등. 하지만 A2A 플러그인이 보여주는 방향성은 명확하다: **에이전트의 미래는 혼자 잘하는 것이 아니라, 함께 잘하는 것에 있다.**

5분짜리 로컬 데모를 직접 돌려보길 권한다. 에이전트가 다른 에이전트에게 작업을 맡기고, 그 결과를 받아서 이어서 처리하는 경험은 — 한번 해보면 돌아갈 수 없는 경험이다.
