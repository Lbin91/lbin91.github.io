DeepSeek가 조용히 있다가 또 한 번 큰 모델을 공개했습니다.

2026년 4월 24일, DeepSeek는 차세대 플래그십 모델군인 **DeepSeek V4 프리뷰**를 공개했습니다. R1이 "중국발 추론 모델 쇼크"에 가까웠다면, 이번 V4는 방향이 조금 다릅니다. 단순히 똑똑한 모델 하나를 낸 것이 아니라, **긴 컨텍스트, 에이전트 작업, 코딩, 비용 효율**을 한 번에 겨냥한 모델 패밀리로 보입니다.

요즘 오픈소스 AI 판을 보면 GLM-5.1, Qwen, Kimi, Gemma가 계속 치고 올라오고 있습니다. 여기에 DeepSeek V4가 꽤 묵직한 선택지를 하나 더 추가했습니다. 개발자 입장에서는 "이걸 채팅 모델로 쓸까?"보다 **"내 터미널 에이전트와 홈 서버에 어떻게 붙일 수 있을까?"**가 먼저 떠오릅니다.

## V4는 하나가 아니라 Pro와 Flash입니다

이번 공개에서 가장 눈에 띄는 부분은 투트랙 구성입니다.

| 모델 | 전체 파라미터 | 활성 파라미터 | 컨텍스트 | 성격 |
|------|--------------|--------------|----------|------|
| **DeepSeek-V4-Pro** | 1.6T | 49B | 1M 토큰 | 고난도 추론, 코딩, 장기 에이전트 작업 |
| **DeepSeek-V4-Flash** | 284B | 13B | 1M 토큰 | 빠른 응답, 저비용 처리, 반복 작업 |

둘 다 MoE(Mixture of Experts) 구조입니다. 전체 파라미터는 매우 크지만, 매 토큰마다 일부 전문가만 활성화해서 계산하는 방식입니다. 그래서 "1.6T면 개인 환경에서는 어렵겠네"로만 끝나는 이야기는 아닙니다. 실제 추론 비용과 체감 속도는 활성 파라미터, 양자화, 서빙 엔진, 메모리 구조에 따라 달라집니다.

개인적으로 더 흥미로운 쪽은 **V4-Flash**입니다. 284B 전체 파라미터에 13B 활성 파라미터라면, 완전한 의미의 노트북용 장난감 모델은 아니지만 로컬 LLM 생태계가 충분히 탐낼 만한 포지션입니다. Mac mini, 중고 GPU 서버, 홈랩 조합으로 "가벼운 에이전트 호출은 로컬에서 처리하고, 어려운 설계는 Pro API로 넘기는" 구성이 더 현실적으로 보이기 시작합니다.

## 1M 컨텍스트가 진짜 포인트입니다

이번 V4에 제목을 하나만 붙인다면 저는 **"백만 토큰 컨텍스트를 실전 비용으로 끌어내리려는 시도"**라고 보고 싶습니다.

DeepSeek는 V4에서 CSA(Compressed Sparse Attention)와 HCA(Heavily Compressed Attention)를 결합한 하이브리드 어텐션 구조를 내세웠습니다. 쉽게 말하면 긴 문서를 전부 같은 밀도로 훑는 대신, 중요한 부분을 더 효율적으로 보겠다는 접근입니다. 공식 모델 카드 기준으로 V4-Pro는 1M 토큰 컨텍스트에서 V3.2 대비 단일 토큰 추론 FLOPs를 27%, KV cache를 10% 수준까지 낮췄다고 설명합니다.

이 부분이 중요한 이유는 에이전트 작업이 결국 컨텍스트 싸움이기 때문입니다.

- 저장소 전체 구조를 읽고 리팩토링 방향을 잡습니다.
- 긴 로그와 테스트 실패 기록을 유지한 채 원인을 추적합니다.
- 문서, 이슈, PR, 코드베이스를 한 세션 안에서 엮어 판단합니다.
- 같은 시스템 프롬프트와 도구 스키마를 반복 호출합니다.

지금까지는 1M 컨텍스트가 있어도 "비싸고 느려서 자주 쓰기 부담스러운 옵션"에 가까웠습니다. V4가 의미 있는 지점은 그 긴 컨텍스트를 **에이전트 루프 안에서 반복적으로 태울 수 있는 가격대와 구조**로 밀고 있다는 점입니다.

## 코딩 모델로 봐도 상당히 강력합니다

DeepSeek는 V4-Pro-Max를 기준으로 코딩과 에이전트 벤치마크에서 꽤 강한 숫자를 제시했습니다.

| 벤치마크 | DeepSeek V4-Pro Max |
|----------|---------------------|
| LiveCodeBench | 93.5 |
| Codeforces Rating | 3206 |
| SWE Verified | 80.6 |
| SWE Pro | 55.4 |
| Terminal Bench 2.0 | 67.9 |

물론 벤치마크는 항상 적당히 의심하면서 봐야 합니다. 실제 프로젝트에서는 레포 구조, 테스트 품질, 프롬프트 하네스, 툴콜 안정성이 더 크게 작용합니다. 그래도 Terminal Bench와 SWE 계열 점수가 같이 올라왔다는 건 의미가 있습니다. 이제 모델 회사들이 "코드 잘 짠다"를 넘어 **터미널에서 오래 버티며 일하는 능력**을 정면으로 경쟁하기 시작했다는 뜻이니까요.

요즘 제가 관심 있게 보는 지점도 바로 여기입니다. Claude Code, Codex, Opencode, Nanobot 같은 터미널 에이전트의 백엔드 모델을 하나로 고정하는 시대는 점점 지나가고 있습니다. 앞으로는 작업 단계별로 모델을 라우팅하는 쪽이 훨씬 자연스러워 보입니다.

- **요구사항 정리:** 저렴한 Flash 계열
- **파일 탐색과 요약:** V4-Flash 또는 GLM 계열
- **핵심 설계 판단:** V4-Pro, Opus, GPT 상위 모델
- **반복 수정과 테스트 루프:** 비용 낮은 코딩 특화 모델
- **최종 리뷰:** 가장 신뢰하는 폐쇄형 모델 또는 Pro급 모델

비싼 모델 하나에게 모든 일을 맡기는 방식은 편합니다. 하지만 에이전트가 20번, 50번, 100번 호출되는 순간부터는 점점 덜 경제적인 선택이 됩니다. 이때부터는 모델 선택이 곧 인프라 설계에 가까워집니다.

## 가격은 DeepSeek답게 공격적입니다

DeepSeek의 무서운 점은 늘 성능보다 가격에서 한 번 더 나옵니다. OpenRouter 기준 V4-Pro는 입력 $1.74/1M 토큰, 출력 $3.48/1M 토큰으로 등록됐고, V4-Flash는 입력 $0.14/1M 토큰, 출력 $0.28/1M 토큰 수준입니다.

이 숫자가 중요한 이유는 단순합니다. 에이전트 워크플로우는 출력보다 **반복 입력 비용**이 더 무섭습니다. 시스템 프롬프트, 도구 정의, 코드 컨텍스트, 로그, 계획 문서가 매 호출마다 계속 들어갑니다. 여기에 캐시 히트까지 잘 먹이면, 동일한 프롬프트 하네스를 반복 호출하는 구조에서 비용 차이가 크게 벌어집니다.

예를 들어 터미널 에이전트가 다음 흐름을 탄다고 해보겠습니다.

1. 저장소 구조를 읽습니다.
2. 관련 파일을 요약합니다.
3. 수정 계획을 세웁니다.
4. 코드를 고칩니다.
5. 테스트 로그를 읽습니다.
6. 실패하면 다시 수정합니다.

이런 루프에서는 "한 번의 답변 품질"보다 **여러 번 불러도 부담 없는 모델**이 더 중요해집니다. V4-Flash가 기대되는 이유도 여기에 있습니다. 모든 일을 Flash에 맡기자는 뜻은 아닙니다. 비싼 모델이 꼭 필요한 순간을 줄여주는 완충재로 꽤 매력적이라는 이야기입니다.

## 로컬 LLM 관점에서는 기대와 현실을 나눠야 합니다

다만 여기서 설레발은 조금 조심해야 합니다. V4-Flash가 13B 활성 파라미터라고 해서 곧바로 "맥북에서 가볍게 돈다"는 뜻은 아닙니다. 전체 파라미터는 284B이고, MoE 모델은 서빙 엔진과 메모리 배치가 중요합니다. 양자화된 가중치, expert 로딩 방식, KV cache 크기, 1M 컨텍스트 사용 여부에 따라 요구 사양은 크게 달라집니다.

그래도 방향은 분명해 보입니다. 로컬 LLM이 예전처럼 "작고 귀여운 실험용 모델"에 머무는 것이 아니라, **API 모델과 역할을 나눠 갖는 실무 구성 요소**가 되고 있습니다.

제가 상상하는 현실적인 구성은 이렇습니다.

- Mac mini나 홈 서버에는 V4-Flash급 모델을 올려 가벼운 요약, 분류, 코드 탐색을 맡깁니다.
- 긴 설계나 복잡한 디버깅은 V4-Pro API 또는 다른 최상위 모델로 라우팅합니다.
- 반복 호출이 많은 에이전트 루프는 Flash를 기본값으로 두고, 실패하거나 애매한 단계에서만 Pro로 승격합니다.
- 민감한 개인 문서나 로컬 프로젝트 인덱싱은 가능하면 로컬 모델로 처리합니다.

이건 "클라우드 API를 완전히 버리자"는 이야기가 아닙니다. 오히려 반대에 가깝습니다. **비싼 API를 더 아껴서, 진짜 필요한 순간에 쓰자는 전략**입니다.

## 그래서 DeepSeek V4는 Opus를 이겼을까요?

이 질문은 늘 자극적이지만, 실무적으로는 별로 좋은 질문이 아니라고 생각합니다.

공식 벤치마크만 보면 V4-Pro Max는 MMLU-Pro에서 GPT-5.4 xHigh와 같은 87.5를 기록했고, LiveCodeBench나 Codeforces 같은 코딩 지표에서는 굉장히 공격적인 숫자를 보여줍니다. 반면 긴 컨텍스트 검색, 복잡한 도구 사용, 섬세한 리팩토링 안정성에서는 여전히 Claude Opus나 Gemini Pro 계열이 더 편하게 느껴지는 구간이 남을 가능성이 큽니다.

그러니까 결론은 "누가 왕이냐"가 아니라 **어디에 꽂아야 제값을 하느냐**입니다.

DeepSeek V4는 특히 이런 작업에 잘 맞아 보입니다.

- 비용이 무서운 장기 코딩 에이전트 루프
- 대량 문서 요약과 코드베이스 맵핑
- 1M 컨텍스트가 필요한 리서치/분석 작업
- 오픈소스 가중치 기반의 자체 서빙 실험
- Pro와 Flash를 섞는 멀티모델 라우팅

반대로 실패 비용이 큰 최종 의사결정, 법률/의료/재무처럼 정확성 검증이 중요한 영역, 아주 섬세한 글쓰기나 제품 카피 작업은 아직 검증을 더 해봐야 합니다. 새 모델이 나왔다고 전부 갈아엎는 건 기술 블로거의 로망일 수 있지만, 운영자 입장에서는 꽤 위험한 선택입니다.

## 마무리하며

DeepSeek V4는 "또 하나의 센 모델"이라기보다, 오픈소스 AI가 다음 단계로 넘어가고 있다는 신호에 가깝습니다.

V4-Pro는 폐쇄형 최상위 모델과 정면으로 붙는 역할을 맡고, V4-Flash는 개발자의 반복 작업과 에이전트 루프를 싸게 깔아주는 역할을 맡습니다. 여기에 1M 컨텍스트와 MIT 라이선스가 붙으니, 실험해볼 이유는 충분합니다.

요즘 AI 개발 환경의 핵심은 점점 명확해지고 있습니다. **가장 똑똑한 모델 하나를 고르는 것이 아니라, 작업 단계마다 가장 합리적인 모델을 배치하는 것.** DeepSeek V4는 그 멀티모델 툴박스에 꽤 강하게 들어올 후보가 됐습니다.

조만간 V4-Flash를 로컬 또는 서드파티 프로바이더로 붙여보고, 실제 터미널 코딩 에이전트에서 어느 정도까지 버티는지 테스트해보려 합니다. 벤치마크 표보다 중요한 건 결국 제 레포에서 테스트가 통과하느냐니까요.
