r/LocalLLaMA에서 Qwen 3.6 27B에 에이전트 검색을 결합해 SimpleQA 벤치마크 95.7%를 달성한 사례가 248업보트를 기록했다. 단일 RTX 3090에서 완전히 로컬로 구동된다.

## 무엇이 달라졌나

LDR(Local Deep Research) 프로젝트의 결과다. 순수 모델 성능만으로는 95.7%에 도달할 수 없다. 에이전트가 웹 검색을 수행하고, 결과를 평가하고, 필요하면 재검색하는 루프를 거치면서 정답률이 크게 올라간다. 모델 자체의 지식 한계를 도구 사용으로 보완한 구조다.

같은 날, Qwen 3.6 27B를 Windows에서 vLLM으로 72 tok/s로 구동하는 방법도 243업보트를 받았다. WSL이나 Docker 없이 네이티브 Windows에서 RTX 3090으로 이 속도가 나온다는 건 윈도우 사용자에게 실질적인 대안이 된다. RTX 6000 Pro에서 Qwen 3.6 27B Q8을 일상 드라이버로 사용하는 후기도 229업보트를 기록했다. "토큰 대청산(Great Token Reckoning)의 시대"라며 비용 절감을 위해 로컬로 전환했다고 밝혔다.

## 비용 효율의 극단

r/DeepSeek에서 DeepSeek V4 Pro에게 100B 규모 LLM 아키텍처를 역설계하고 llama.cpp에 적응시키는 작업을 시켰더니 약 1,000만 토큰, $2 미만으로 완수했다는 글이 206업보트를 받았다. DeepSeek V4 Flash의 가격은 "$900짜리 작업을 $4.74에"라는 표현으로 요약됐다(110업보트).

## 에이전트의 자가 개선 실험

DeepSeek V4 Pro 에이전트에게 자기 소스 코드에 접근 권한을 주고 스스로 개선하라고 지시했더니 23번의 커밋으로 메모리 시스템을 최적화했다는 실험도 64업보트를 기록했다. 코드를 수정하고 테스트하고 커밋하는 전체 사이클을 자율적으로 수행한 사례다.

## 에이전트 실제 도입, 어디까지 왔나

r/AI_Agents에서 "30개 이상 AI 에이전트로 회사를 운영한다는 사람, 실제인가 환상인가?"라는 질문이 17업보트, 79개 댓글로 긴 토론을 불러일으켰다. 15년차 소프트웨어 엔지니어가 던진 질문에, 실제로 에이전트를 운영 중인 창업자들과 환상을 경계하는 엔지니어들의 의견이 팽팽하게 교차했다. 핵심 쟁점은 "에이전트가 코딩은 잘하지만, 기획과 제품 방향, 사용자 피드백 처리에서는 여전히 사람이 필요하다"는 점이었다.

## 시사점

에이전트 + 로컬 모델의 조합이 벤치마크에서 실질적인 성과를 내기 시작했다. 단일 3090으로 95.7% SimpleQA는 상용 API 없이도 연구 수준의 에이전트 워크플로우가 가능하다는 것을 보여준다. 다만 프로덕션 환경에서의 신뢰성은 여전히 논쟁거리다.
